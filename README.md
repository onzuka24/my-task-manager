# my-task-manager

常駐型のタスク管理ツール。

リストを正確に保つためのツールではない。**タスクとタスクの「あいだ」を扱うための常駐
ツールである。** 生産性を奪っているのはリストの不正確さではなく切り替えの失敗であり、
本ツールは移行の瞬間に立ち会うことを設計の中心に置く — 切り替えの瞬間に「どこで止まった
か」を引き取り、再開の瞬間に「全体のどこにいるか」を返す。

利用者は作者ひとり (solo / personal) である。配布も自動更新も行わない。

## 設計上の三つの賭け

1. **一度に見せるのは「次の一手」だけ。** 全体像は要求されたときにのみ開示する。
2. **タスクは平坦な項目ではなく、順序を持つ工程である。** 再開時に必要なのは「何をやるか」
   ではなく「全体 No.1〜N のうち、自分がどこにいるか」である。
3. **摩擦は書き留めることではなく、リストの手入れにある。** 放置されたタスクを健全に
   劣化・消滅させる責務をツールが負う。

詳細は `_bmad-output/planning-artifacts/prds/` の PRD と
`_bmad-output/planning-artifacts/architecture/` のアーキテクチャスパインにある。

## 動作環境

- macOS (Apple Silicon / Intel)
- Rust 1.98.1 (`rust-toolchain.toml` が固定する)
- Node.js + pnpm 11 (`package.json` の `packageManager` が固定する)

## 導入

```sh
make            # ビルドして /Applications に配置する
make open       # 配置したアプリを起動する
make stop       # 常駐プロセスを終了させる
make uninstall  # 常駐を止め、自動起動の印・アプリデータ・ログごと消す
```

`make dev` で開発用の実行、`make test` と `make lint` で検査を回せる。

初回起動でログイン時の自動起動が登録される。解除したあとの起動がそれを覆すことはない。

## 使い方

### 呼び出し

| 操作 | 結果 |
| --- | --- |
| `Control + Option + Space` | オーバーレイの開閉。どのアプリが最前面でも効く |
| メニューバー項目 → 開く | 同じくオーバーレイを開く。ホットキーが他のアプリに奪われたときの副の経路 |
| メニューバー項目 → 終了 | **唯一の明示的な終了経路。** `Cmd+Q` は無効化してある |

メニューバー項目にはホットキーの登録状態も 1 行で出る。

オーバーレイは呼び出して使ったら消える一時的な面である。閉じるのは Esc・フォーカス離脱
であり (切り替えそのものでは閉じない)、閉じた時点で開いていた面と入力途中の下書きは破棄される — 次の呼び出しは必ず
「次の一手」だけの初期表示から始まる。

### 既定表示 — 次の一手

現在地のステップと「第 N ステップ / 全 M ステップ」、そして中断メモの入力欄だけが出る。
他のタスクの名前も、他のステップの内容も現れない。

| 打鍵 | ボタン | 結果 |
| --- | --- | --- |
| `Enter` | 切り替え | メモを確定し、同一タスクの次のステップへ移る。**オーバーレイは閉じず**、移った先を見せる |
| `⌘Enter` | 完了 | メモと完了を確定し、**現在地はそのままで**一覧を開く |
| `⌘D` | 待機 / 主作業に戻る | 主作業を戻り先として覚えたまま待機に入る。待機中なら主作業へ戻る |
| `⌘E` | タスク修正 | 現在地のタスクの題名とステップを直す |
| `⌘R` | 休息 | 現在地を保ったまま非活性にし、連続作業時間の計数を止める |
| `⌘N` | 新規タスク | タスクを作る |
| `⌘I` | 思いつき | 思いつきを一行で置く (休息中も使える) |
| `⌘L` | タスク一覧 | 全体像を開示する |
| `⌘/` | 「ショートカット」の見出し | 打鍵の案内を開閉する |
| `Esc` | 閉じる | 何も確定せずに閉じる |

作業中のボタンは三つのまとまりに分かれる — [完了] [切り替え] [思いつき] [待機 / 主作業に戻る]
と [新規タスク] [タスク修正] [タスク一覧] が間を空けて横に並び (窓の幅が足りなければ後者は
下へ折り返す)、その下に [休息] [閉じる] が並ぶ。未着手 (現在地が無い) のときは
[新規タスク] [タスク一覧] [閉じる] だけが並ぶ。打鍵の案内は見出し
「▸ ショートカット」の 1 行に畳まれており、`⌘/`（または見出し）で開くと打鍵ごとに 1 行で
並ぶ。ホットキーが登録できていれば、その打鍵 (オーバーレイの開閉) も一覧に載る。
開閉の状態は常駐が動いている間だけ覚える (休息中・未着手の既定表示でも同じ)。

中断メモは省略してよい。提示された既存のメモに触れずに確定した場合、「メモを書いた」とは
記録されない。欄を空にして確定すると、既存のメモは消える (これも「メモを書いた」とは
記録されない)。

**切り替えはオーバーレイを閉じない。** 移った先の次の一手・位置情報・中断メモが既定表示
として出て、切り替えた旨が 1 行添えられる。確かめたら `Esc` で閉じる。そこでもう一度
`Enter` を押すと、さらに次のステップへ切り替わる。

**完了は現在地の移動から導出されない。** `⌘Enter` が現在地を動かさないのはそのためで
あり、次にどのステップへ着手するかは開いた一覧から選ぶ。

### 休息

`⌘R` で休息に入る。**介入を待つ必要はない** — 閾値より前に離席する日は当然にあり、
宣言しなければ離席の間も連続作業時間が伸びて、戻った直後に介入が出る。

休息中は表示が入れ替わり、現在地が保たれていることだけを述べる。次の一手も、休んでいる
長さも出さない。`Enter`（または「休息を終える」）が休息の終了の宣言であり、連続作業時間は
そこから数え直される。

休息中の表示には「休息のすすめ」(遠くを眺める・水を飲む・スマホを見ない・肩と首を
ほぐす など、緊張型頭痛を防ぐ過ごし方) が見出し 1 行で出る。`⌘T`（または見出し）で
開閉する。開閉の状態は常駐が動いている間だけ覚え、次の休息へ引き継がれる。
休息中のボタンは「休息を終える」「新規タスク」「タスク一覧」「閉じる」で、`⌘/` で開く打鍵の
案内も休息中のもの (`Enter` で休息を終える・`⌘T` で休息のすすめ ほか) に入れ替わる。

連続作業時間が閾値 (既定 50 分) を超えると、ツール側から介入のパネルが出る。入力先は
奪わないので、打鍵の途中でも作業を止めずに済む。応答は `Control + Option + R`（休息する）
と `Control + Option + G`（猶予）である。

休息に入ってから休息の長さ (既定 10 分) が経つと、同じパネルで戻るきっかけが出る。
応答は同じ二つの打鍵で、`Control + Option + R` が「休息を終える」、`Control + Option + G`
が「もう少し休む」である。「休息を終える」を選ぶと現在地が活性へ戻り、連続作業時間が
数え直され、オーバーレイが開いて次の一手が出る。「もう少し休む」は休息の長さの後に
出直す (何度でも)。**時間が来ても休息は自動では終わらない** — 促すだけである。スリープ
していた時間も休息に含める。休息の開始時刻は保存しないため、休息中に常駐を終了して
起動し直すと、起動した時刻から数える。

戻るきっかけのパネルは**応答するまで消えない**。自分で (`Enter` で) 休息を終えても
残り、そのときの応答は次のとおりである。

- 「休息を終える」— 休息は既に終わっているので何も書かず、オーバーレイを開くだけである。
- 「もう少し休む」— 何も予約しない。パネルが消えるだけである。

パネルを残すことで、次の二つが起きる。

- **残ったパネルに応答するまで、休息の介入 (連続作業時間の閾値) は出ない。** パネルは
  同時に一つだけだからである。
- **新しい休息に入った後で、古いパネルの「休息を終える」を選ぶと、新しい休息が終わる。**
  パネルは種類を見て応答するだけで、どの休息に対して出たものかを区別しない。

### 待機 (`⌘D`)

AI の出力待ちなどで主作業を離れ、短い別作業 (情報収集・AI への相談・別タスクの小さな
ステップ) をするときに使う。作業中の既定表示で `⌘D` を押すと待機の面が開く。分数の欄
(初期値は待機の長さ、既定 5 分) と「何を待っているか」の一行 (省略可) を書き、`Enter` で
待機に入る (`Esc` で戻る)。分数が正の整数でなければ入らず、理由が 1 行出る。休息中・
未着手では `⌘D` は何もしない。

- 待機に入った時点の現在地が**戻り先**になる。待機中は一覧 (`⌘L`) から別タスクの
  ステップへ現在地を移してよく、戻り先は変わらない。
- 待機中の既定表示には次の一手に「待機中 — <何を待っているか>」が 1 行添う。**残り時間・
  経過・回数はどこにも出ない。** 連続作業時間は数え続け、休息の介入は通常どおり出る。
- 待機の長さが経つと、休息と同じパネルで「主作業に戻る」(`Control + Option + R`) と
  「あと少し」(`Control + Option + G`) が出る。「主作業に戻る」は、別のタスクにいれば現在地を
  戻り先へ移し (切り替え履歴に 1 行)、戻り先と同じタスクの中にいれば (第 3 から第 4 へ
  進めていた場合も) 動かさず何も書かない。どちらでも待機を終え、オーバーレイを開いて主作業の次の一手と
  中断メモの欄を見せる。「あと少し」は待機に入ったときの分数の後に出直す (何度でも)。
  **時間が来ても待機は自動では終わらない。** 他の介入のパネルが出ている間は待つ。
- 待機中に `⌘D` を押せば早めに戻れる。中断メモの欄に書きかけがあり、いまの現在地が
  戻り先と別のタスクにあれば、その書きかけは離れる側のステップの中断メモとして確定する (切り替えと
  同じ扱い)。
- 待機中に休息に入る (`⌘R` または休息の介入) と、先に現在地を戻り先へ戻してから休息に
  入り、待機を終える (同じタスクの中にいれば戻さない)。休息明けに主作業へ戻れるようにするためである。
- 戻り先・期限・何を待っているかは保存しない。待機中に常駐を終えると待機は消え、現在地は
  その時点のまま残る。
- 待機の介入のパネルが出ている間に `⌘D` で戻るか休息に入ると、待機が終わり、パネルは
  消える (応答を待たずに取り下げる)。取り残されたパネルが休息の介入を塞いだり、休息中に
  オーバーレイを開いたり、新しい待機を終えたりしない。

### タスク一覧 (`⌘L`)

タスクの見出しはすべて並び、ステップは**一度に一つのタスクの分だけ**が続く。

| 打鍵 | 結果 |
| --- | --- |
| `↑` `↓` | 行を選ぶ (見出しにも止まる) |
| `Enter` (見出し) | そのタスクのステップを開く。**現在地は動かない** |
| `Enter` (ステップ) | そこへ現在地を移す |
| `Enter` (思いつき) | 作成の面を開く (タスクへの昇格) |
| `⌘E` | タスク修正 — 選んでいる行のタスクを直す |
| `Esc` | 既定表示へ戻る (オーバーレイは閉じない) |

**全ステップの完了を宣言したタスクは一覧から消える。** データは消えない — 表示から
外れるだけである。現在地を抱えている間は残り、そこを離れた時点で消える。

思いつきが 1 件以上あれば、一覧の末尾に見出し「思いつき」と、新しい順の行が並ぶ (0 件
なら欄ごと出ない)。

### 思いつき (`⌘I`)

作業中に別の作業を思いついたら、`⌘I` で一行の入力欄を開いて書き、`Enter` で置く。
**現在地・中断メモ・休息のいずれにも触れない。** 置いた後もオーバーレイは閉じず、既定
表示へ戻って「思いつきを置いた。」と 1 行出る。`Esc` で何も置かずに戻る。

- 思いつきは既定表示にもメニューバー項目にも出ない。件数も、置いてからの経過も出ない。
- 一覧の思いつきの行で `Enter` を押すと、題名とステップ 1 の両方に思いつきの文が入った
  作成の面が開く。`⌘Enter` 一打でタスクへ昇格し、その思いつきは消える (必要なら直して
  から確定する)。作成の面を `Esc` で出れば思いつきは残る。
- **昇格しなかった思いつきは、置いてから 14 日 (思いつきの寿命) を過ぎると黙って消える。**
  消えたことは知らせない。寿命は `setting` 表の `idea_lifetime_seconds` で変えられる
  ([docs/settings.md](docs/settings.md))。
- 思いつきを手で消す・並べ替える・直す経路は無い。

### タスクを作る (`⌘N`)

題名と、1 行 = 1 ステップの本文を打つ。`⌘Enter` で作成のみ、`⌘⇧Enter` で作成して
その第 1 ステップへ着手する。素の `Enter` は改行である。

ステップを 1 個も持たないタスクは作れない。

### タスクを直す (`⌘E`)

打ち間違えた題名やステップを後から直す面である。

- 題名の欄が 1 つ、**既存のステップごとに欄が 1 つ**、末尾に追記用の欄 (1 行 = 1 ステップ) が
  並ぶ。
- `⌘Enter` で保存、`Esc` で破棄。素の `Enter` は改行である。
- **現在地・完了・中断メモのいずれも変わらない。** 直すのは文字だけである。
- **消す経路は無い。** 空にしたステップは削除ではなく誤りとして拒まれる。並べ替えも
  できない。

## データとログ

| 置き場所 | 中身 |
| --- | --- |
| `~/Library/Application Support/dev.onzuka.mytaskmanager/` | SQLite の状態と自動起動の印 |
| `~/Library/Logs/dev.onzuka.mytaskmanager/` | ログ (**ローカルのみ。外部送信は行わない**) |
| `~/Library/LaunchAgents/my-task-manager.plist` | 自動起動の登録 |

中断メモの本文とタスクの題名はログに書かれない。記録されるのは「起きた」という事実だけ
である。

休息の閾値 (`rest_threshold_seconds`)・猶予 (`grace_period_seconds`)・休息の長さ
(`rest_length_seconds`)・待機の長さ (`wait_length_seconds`) は SQLite の `setting` 表に
あり (いずれも秒)、変更する面はまだない。値が無い・0 以下・数値でなければ既定値
(3000 / 900 / 600 / 300) を使う。

## 開発

```sh
make test   # cargo test → pnpm check → pnpm test
make lint   # cargo fmt --check → cargo clippy -D warnings
```

判断は純粋関数へ切り出し、OS や生きた Tauri アプリを起動せずに検証できる形にしてある。
コマンド境界の型 (`src-tauri/src/commands/mod.rs`) と `src/overlay/Overlay.svelte` の
TypeScript 型は 1:1 で対応しており、`invoke<T>` は実行時検査を行わない — 片方だけ変えても
警告は出ないため、Rust 側のワイヤ契約テストが形を固定している。

未着手の判断と申し送りは `_bmad-output/implementation-artifacts/deferred-work.md` にある。
