# my-task-manager

常駐型のタスク管理ツール。

リストを正確に保つためのツールではない。**タスクとタスクの「あいだ」を扱うための常駐
ツールである。** 生産性を奪っているのはリストの不正確さではなく切り替えの失敗であり、
本ツールは移行の瞬間に立ち会うことを設計の中心に置く — 切り替えの瞬間に「どこで止まった
か」を引き取り、再開の瞬間に「全体のどこにいるか」を返す。

利用者は作者ひとり (solo / personal) である。配布も自動更新も行わない。

## 設計上の三つの賭け

1. **一度に見せるのは「次の一手」だけ。** 全体像は要求されたときにのみ開示する。
2. **タスクは平坦な項目ではなく、順序を持つ工程である。** 再開時に必要なのは「何をやるか」
   ではなく「全体 No.1〜N のうち、自分がどこにいるか」である。
3. **摩擦は書き留めることではなく、リストの手入れにある。** 放置されたタスクを健全に
   劣化・消滅させる責務をツールが負う。

詳細は `_bmad-output/planning-artifacts/prds/` の PRD と
`_bmad-output/planning-artifacts/architecture/` のアーキテクチャスパインにある。

## 動作環境

- macOS (Apple Silicon / Intel)
- Rust 1.98.1 (`rust-toolchain.toml` が固定する)
- Node.js + pnpm 11 (`package.json` の `packageManager` が固定する)

## 導入

```sh
make            # ビルドして /Applications に配置する
make open       # 配置したアプリを起動する
make stop       # 常駐プロセスを終了させる
make uninstall  # 常駐を止め、自動起動の印・アプリデータ・ログごと消す
```

`make dev` で開発用の実行、`make test` と `make lint` で検査を回せる。

初回起動でログイン時の自動起動が登録される。解除したあとの起動がそれを覆すことはない。

## 使い方

### 呼び出し

| 操作 | 結果 |
| --- | --- |
| `Control + Option + Space` | オーバーレイの開閉。どのアプリが最前面でも効く |
| メニューバー項目 → 開く | 同じくオーバーレイを開く。ホットキーが他のアプリに奪われたときの副の経路 |
| メニューバー項目 → 終了 | **唯一の明示的な終了経路。** `Cmd+Q` は無効化してある |

メニューバー項目にはホットキーの登録状態も 1 行で出る。

オーバーレイは呼び出して使ったら消える一時的な面である。Esc・フォーカス離脱のどちらでも
閉じ、閉じた時点で開いていた面と入力途中の下書きは破棄される — 次の呼び出しは必ず
「次の一手」だけの初期表示から始まる。

### 既定表示 — 次の一手

現在地のステップと「第 N ステップ / 全 M ステップ」、そして中断メモの入力欄だけが出る。
他のタスクの名前も、他のステップの内容も現れない。

| 打鍵 | ボタン | 結果 |
| --- | --- | --- |
| `Enter` | 切り替え | メモを確定し、同一タスクの次のステップへ移ってオーバーレイを閉じる |
| `⌘Enter` | 完了して次を選ぶ | メモと完了を確定し、**現在地はそのままで**一覧を開く |
| `⌘E` | このタスクを直す | 現在地のタスクの題名とステップを直す |
| `⌘N` | 新しいタスク | タスクを作る |
| `⌘L` | 一覧 | 全体像を開示する |
| `Esc` | 閉じる | 何も確定せずに閉じる |

中断メモは省略してよい。提示された既存のメモに触れずに確定した場合、「メモを書いた」とは
記録されない。

**完了は現在地の移動から導出されない。** `⌘Enter` が現在地を動かさないのはそのためで
あり、次にどのステップへ着手するかは開いた一覧から選ぶ。

休息中は表示が入れ替わり、`Enter` は休息の終了の宣言だけを意味する。

### 一覧 (`⌘L`)

タスクの見出しはすべて並び、ステップは**一度に一つのタスクの分だけ**が続く。

| 打鍵 | 結果 |
| --- | --- |
| `↑` `↓` | 行を選ぶ (見出しにも止まる) |
| `Enter` (見出し) | そのタスクのステップを開く。**現在地は動かない** |
| `Enter` (ステップ) | そこへ現在地を移す |
| `⌘E` | 選んでいる行のタスクを直す |
| `Esc` | 既定表示へ戻る (オーバーレイは閉じない) |

**全ステップの完了を宣言したタスクは一覧から消える。** データは消えない — 表示から
外れるだけである。現在地を抱えている間は残り、そこを離れた時点で消える。

### タスクを作る (`⌘N`)

題名と、1 行 = 1 ステップの本文を打つ。`⌘Enter` で作成のみ、`⌘⇧Enter` で作成して
その第 1 ステップへ着手する。素の `Enter` は改行である。

ステップを 1 個も持たないタスクは作れない。

### タスクを直す (`⌘E`)

打ち間違えた題名やステップを後から直す面である。

- 題名の欄が 1 つ、**既存のステップごとに欄が 1 つ**、末尾に追記用の欄 (1 行 = 1 ステップ) が
  並ぶ。
- `⌘Enter` で保存、`Esc` で破棄。素の `Enter` は改行である。
- **現在地・完了・中断メモのいずれも変わらない。** 直すのは文字だけである。
- **消す経路は無い。** 空にしたステップは削除ではなく誤りとして拒まれる。並べ替えも
  できない。

## データとログ

| 置き場所 | 中身 |
| --- | --- |
| `~/Library/Application Support/dev.onzuka.mytaskmanager/` | SQLite の状態と自動起動の印 |
| `~/Library/Logs/dev.onzuka.mytaskmanager/` | ログ (**ローカルのみ。外部送信は行わない**) |
| `~/Library/LaunchAgents/my-task-manager.plist` | 自動起動の登録 |

中断メモの本文とタスクの題名はログに書かれない。記録されるのは「起きた」という事実だけ
である。

休息の閾値と猶予は SQLite の `setting` 表にあり、変更する面はまだない。

## 開発

```sh
make test   # cargo test → pnpm check → pnpm test
make lint   # cargo fmt --check → cargo clippy -D warnings
```

判断は純粋関数へ切り出し、OS や生きた Tauri アプリを起動せずに検証できる形にしてある。
コマンド境界の型 (`src-tauri/src/commands/mod.rs`) と `src/overlay/Overlay.svelte` の
TypeScript 型は 1:1 で対応しており、`invoke<T>` は実行時検査を行わない — 片方だけ変えても
警告は出ないため、Rust 側のワイヤ契約テストが形を固定している。

未着手の判断と申し送りは `_bmad-output/implementation-artifacts/deferred-work.md` にある。
