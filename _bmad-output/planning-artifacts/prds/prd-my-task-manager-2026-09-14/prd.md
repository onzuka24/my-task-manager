# PRD: my-task-manager
*仮称 — 未確定 (§10 OQ-7)*

## 0. この文書について

本 PRD は作者自身が単独で開発・利用するツールの要求定義である。読者は作者本人、および本文書を入力とする下流のワークフロー (アーキテクチャ設計、UX 設計、エピック/ストーリー分解) を想定する。

構成は次のとおりである。§3 用語集が語彙を固定し、以降の全セクションはそこで定義された語のみを使用する。§4 機能では機能領域ごとにまとまりを作り、その下に機能要件 (FR) を通し番号で入れ子にする。実現手段・技術選定は本文書の対象外であり、検討経緯とともに `addendum.md` に分離した。未確認の推論は本文中に `[ASSUMPTION]` として埋め込み、§11 に集約した。下流への申し送りは `[NOTE FOR PM]` として本文中に置き、未決事項であるものは §10 に ID 付きで集約した。

先行する入力文書は存在しない。本文書は対話による要求の引き出しのみから作成された。

## 1. ビジョン

my-task-manager は、タスクを記録・整理するためのツールではない。**タスクとタスクの「あいだ」を扱うための常駐ツールである。**

従来のタスク管理ツールは、リストを正確に保つことを目的として設計されている。しかし実際に生産性を奪っているのはリストの不正確さではなく、**切り替えの失敗**である。作業を中断されれば元の場所に戻るのに時間がかかり、切り替えるべき場面で固着して惰性のまま時間を溶かし、そして切り替えた後も前のタスクが頭に注意残余 (attention residue) として残り続け、新しいタスクに注意を全量投入できない。二つのタスクに同時に家賃を払っている状態が常態化している。

そこで本ツールは、リストの管理ではなく**移行の瞬間**に立ち会うことを設計の中心に置く。グローバルホットキーで常に呼び出せる常駐プロセスとして動作し、切り替えの瞬間に「どこで止まったか」を引き取り、再開の瞬間に「全体のどこにいるか」を返す。目的は切り替えを**速く**することではなく、**完了させる**ことにある — 前のタスクが手放されて初めて、次のタスクは注意を受け取れる。

同時に本ツールは、ユーザーからの呼び出しを待つだけの受動的な道具ではない。スケジュールの逸脱と休息の欠落という、ユーザーが自力では管理しきれていない二点については、ツール側から能動的に働きかける。

### 1.1 設計上の三つの賭け

1. **(#1) 一度に見せるのは「次の一手」だけ。** 過去に破綻したプレーンテキストの TODO リストは、肥大化し未来のタスクを大量に可視化したことで、目の前の一手への集中を奪った。全体像は要求されたときにのみ開示する。
2. **(#2) タスクは平坦な項目ではなく、順序を持つ工程である。** 再開時に必要な情報は「何をやるか」ではなく「全体 No.1〜N のうち、自分がどこにいるか」である。
3. **(#3) 摩擦は capture (書き留め) ではなく grooming (リストの手入れ) にある。** 書き留めること自体は苦ではない。リストが腐り、罪悪感の山に変わっていくことが苦なのである。したがって本ツールは、放置されたタスクを健全に劣化・消滅させる責務を負う。

## 2. 対象ユーザー

本ツールの利用者は作者自身 (以下 Onzuka) ただ一人である (solo / personal)。合意形成のためのペルソナ定義は行わず、満たすべき仕事 (JTBD) のみを列挙する。

### 2.1 Jobs To Be Done

- **機能的** — 中断された作業に、再入のコストを払わずに戻りたい。
- **機能的** — 一日の計画から逸脱したことに、その日のうちに気づきたい (翌日ではなく)。
- **情緒的** — 切り替えた後に前のタスクを頭から手放したい。二つのタスクに同時に注意を払う状態から解放されたい。
- **情緒的** — リストを見て罪悪感を覚えたくない。放置されたタスクが積み上がっていく感覚を避けたい。
- **文脈的** — 作業の流れを止めずに記録したい。ツールを開くという行為自体が中断であってはならない。
- **身体的** — 適切な休息を取りたい。自力では取れていない。

### 2.2 主要ユーザージャーニー

*solo 用途のため軽量表記とする。§4 の各 FR は本節の UJ-n を参照する。*

- **UJ-1: 割り込みから戻る。** 作業中に別件が差し込まれ、Onzuka はホットキーでオーバーレイを呼び出し、止まった地点を数秒で記録して離脱する。後刻戻ったとき、オーバーレイは「どのタスクの No.3 にいるか」と中断メモを提示し、彼は読み直しの時間を払わずに再開する。
- **UJ-2: 交差に気づく。** 本日計画は次のタスクへの移行時刻を過ぎているが、Onzuka は現在のステップの途中にいる。ツールが介入し、交差の存在を明示する。彼は「このステップを終わらせてから移る」「ここで中断して移る」のいずれかを選択し、どちらを選んでも決定した事実が記録される — 決めないまま時間が流れる状態が解消される。
- **UJ-3: 休息に追い出される。** 連続作業時間が閾値を超え、ツールが休息の介入を発する。Onzuka は現在地を保持したまま離席し、戻ったときに現在地がそのまま提示される。

## 3. 用語集

*以降の全セクションは本節の用語を厳密に使用する。同義語の導入は禁止する。*

- **タスク (Task)** — 一つの達成対象。1 個以上の**ステップ**を順序付きで内包する。
- **ステップ (Step)** — **タスク**内の作業単位。タスク内で No.1 から No.N まで通し番号を持つ。着手前に概ね定義され、進行中に詳細が追記されうる。タスクに対して 1..N。**完了**の状態を持つ。
- **完了 (Completion)** — **ステップ**に対してユーザーが明示的に宣言する状態。**現在地**の位置からは導出されない — **現在地**が前の**ステップ**へ戻っても、後続の**ステップ**の**完了**は取り消されない。
- **現在地 (Current Position)** — 「どの**タスク**の第何**ステップ**にいるか」を指す唯一のポインタ。システム全体で同時に一つのみ存在する。**活性**と**非活性**の二状態を持ち、**休息**中は**非活性**となるが値は保持される。値を持たない状態は未着手時のみである。
- **次の一手 (Next Action)** — **現在地**が指している**ステップ**そのもの。既定の表示単位であり、**オーバーレイ**が何も操作されていない状態で見せる唯一の項目。
- **中断メモ (Interruption Note)** — **現在地**を離れる際に記録される、再開に必要な最小限の文脈。ステップに対して 0..1。
- **本日計画 (Day Plan)** — その日に取り組む**タスク**の順序付き列。各タスクに想定の時間配分を持つ。一日に対して 0..1。
- **ずれ (Drift)** — **本日計画**が想定する進行と、**現在地**の実際の進行との差分。
- **交差 (Crossing)** — **本日計画**が次の**タスク**への移行を要求している一方で、**現在地**が**ステップ**の途中にある状態。**ずれ**の特殊形であり、本ツールが検出対象とする中心的な状態。
- **切り替え (Switch)** — **現在地**をあるステップから別のステップへ移す操作。**中断メモ**の記録を伴う。
- **オーバーレイ (Overlay)** — グローバルホットキーにより最前面へ呼び出される UI。**常駐プロセス**の唯一の可視面。
- **常駐プロセス (Resident Process)** — 常時バックグラウンドで動作し、ホットキー受付・**ずれ**検出・**介入**の発火を担う実行主体。
- **介入 (Intervention)** — **常駐プロセス**がユーザーの呼び出しを待たずに発する能動的な通知。**交差**と**休息**の二つの契機を持つ。
- **休息 (Rest)** — 作業から離れている状態。**現在地**は値を保持したまま**非活性**となる。**連続作業時間**の計数は停止する。
- **腐敗 (Decay)** — 長期間**現在地**にならなかった**タスク**の状態変化。表示から外れていく過程を指す。
- **観測 (Observation)** — **常駐プロセス**が最前面のアプリケーションおよびウィンドウの識別情報 (アプリケーション名とウィンドウタイトル。文書の内容および URL の全体は含まない) を継続的に取得する行為。
- **作業文脈 (Work Context)** — **観測**により得られた、最前面のアプリケーション名とウィンドウタイトルの組。同一とみなす粒度は v1 の対象外である。
- **固着 (Fixation)** — **本日計画**が次の**タスク**への移行を要求しているか否かに関わらず、**現在地**が更新されないまま単一の作業文脈が閾値を超えて継続している状態。
- **連続作業時間 (Continuous Work Time)** — 直近に**現在地**が**活性**となった時点からの経過時間。**休息**中は計数されない。
- **猶予 (Grace Period)** — **介入**に対して「現在の**ステップ**を完了させてから移行する」が選ばれたときに与えられる延長時間。
- **再入 (Re-entry)** — 中断された**ステップ**が再び**現在地**となり、作業が再開されること。

## 4. 機能

*各サブセクションは一つのまとまった機能を表す。FR は文書全体で通し番号を持つ (FR-1〜FR-21)。番号は安定であり、機能の再編があっても振り直さない。技術的な実現手段は本節の対象外であり、`addendum.md` に記録する。*

### 4.1 常駐・呼び出し・既定表示

**説明:** ツールは**常駐プロセス**として動作し、ユーザーが明示的に起動する行為を必要としない。呼び出しはグローバルホットキー一つに集約され、**オーバーレイ**が最前面に現れる。UJ-1 を実現する。ここでの設計原則は「ツールを開くことが中断であってはならない」であり、したがって呼び出しから記録完了までの操作は数秒で完結しなければならない。開いた**オーバーレイ**が既定で何を見せるかも本節が定める。

#### FR-1: ホットキーによる呼び出し

ユーザーは、いかなるアプリケーションが最前面にあっても、単一のグローバルホットキーで**オーバーレイ**を呼び出せる。UJ-1 を実現する。

**結果 (検証可能):**
- ホットキー押下から**オーバーレイ**の入力受付開始までが 300ms 以内である。
- 呼び出し前に最前面であったアプリケーションは、**オーバーレイ**を閉じた時点でフォーカスを回復する。
- **オーバーレイ**は Esc キー単独で閉じられる。

#### FR-2: 既定表示の最小化

**オーバーレイ**は、追加操作のない初期状態において**次の一手**のみを表示する。設計上の賭け #1 を実装する。

**結果 (検証可能):**
- 初期表示に、二つ以上の**タスク**の名称または二つ以上の**ステップ**の内容が同時に現れない。
- **タスク**の全体像および一覧は、ユーザーの明示的な操作によってのみ開示される。
- ただし**現在地**の所在を示す位置情報 (例: 「第 3 ステップ / 全 6 ステップ」) は初期表示に含まれる。これは一覧の開示ではなく、設計上の賭け #2 に基づく再入支援である。

#### FR-3: 常駐と自動復帰

**常駐プロセス**はログイン時に自動的に起動し、明示的な終了操作があるまで動作を継続する。

**結果 (検証可能):**
- OS 再起動後、ユーザーの操作なしに**常駐プロセス**が動作している。
- **常駐プロセス**が異常終了した場合、**切り替え**の完了時点までに確定した**現在地**と**中断メモ**は失われない。入力途中で確定していない**中断メモ**は失われてよい。

### 4.2 タスクとステップ

**説明:** **タスク**は平坦な項目ではなく、順序を持つ**ステップ**の列として扱われる (設計上の賭け #2)。**ステップ**は着手前に概ね定義されるが、作業の実態に合わせて進行中に追記できる。完全な事前設計を強制すればツールは計画ツールになり、逆に構造を持たなければ再入時に位置を示せない — 本機能はその中間を狙う。

#### FR-4: タスクとステップの定義

ユーザーは**タスク**を作成し、その内部に順序を持つ**ステップ**を定義できる。

**結果 (検証可能):**
- **ステップ**は作成順ではなく明示的な順序を持ち、タスク内で No.1 から連番が振られる。
- **ステップ**を持たない**タスク**は作成できない (最低 1 個)。
- ユーザーは**ステップ**の**完了**を明示的に宣言できる。**完了**は**現在地**の移動によって自動的に付与も取り消しもされない。

#### FR-5: 進行中のステップ追記

ユーザーは作業の途中で、現在の**タスク**に**ステップ**を追加または分割できる。

**結果 (検証可能):**
- **ステップ**の追加により後続の**ステップ**の連番が再計算されても、**現在地**は同一の作業単位を指し続ける。
- **ステップ**を分割した場合、**現在地**は分割後の前半を指す (未着手部分ではなく作業中の部分を指し続ける)。
- 分割対象の**ステップ**に**中断メモ**が存在する場合、**中断メモ**は分割後の前半に帰属する。

#### FR-6: 現在地の一意性

**現在地**はシステム全体で同時に一つしか存在しない。

**結果 (検証可能):**
- 新たな**ステップ**が**現在地**となった時点で、直前の**現在地**は自動的に解除される。
- **現在地**が値を持たない状態は未着手時に限られ、**休息**中も値は保持される。

#### FR-19: 全体像の開示面

ユーザーは明示的な操作により、**タスク**および**ステップ**の一覧を開示できる。この面は既定では表示されず、FR-2 の最小表示から意図的な操作を経てのみ到達する。FR-9、FR-17、FR-18 はいずれも本開示面を前提とする。

**結果 (検証可能):**
- 開示面は**オーバーレイ**の初期表示から到達するために、ユーザーの明示的な操作を最低 1 回必要とする。
- 開示面は**オーバーレイ**を閉じた時点で破棄され、次回の呼び出し時に初期表示 (FR-2) へ戻る。開示状態は保持されない。
- 開示面は**腐敗**した**タスク**を含まない (FR-18 の経路と区別される)。

### 4.3 切り替えと再開

**説明:** 本ツールの中核。**切り替え**は単なる**現在地**の移動ではなく、**中断メモ**の記録を伴う儀式として定義される。目的は切り替えを速くすることではなく完了させることであり、前の**タスク**を頭から手放すためのクロージャを与えることにある。UJ-1 を実現する。

#### FR-7: 中断メモの記録

ユーザーが**切り替え**を行う際、システムは離脱する**ステップ**に対する**中断メモ**の入力機会を提示する。

**結果 (検証可能):**
- **中断メモ**の入力は省略可能であり、省略しても**切り替え**は完了する (入力必須にすると切り替えを避ける動機が生まれるため)。
- 記録された**中断メモ**は、当該**ステップ**が再び**現在地**となったときに自動的に提示される。
- 同一の**ステップ**から二度目以降の**切り替え**を行う場合、既存の**中断メモ**は上書きされる。上書き前の内容は記録時点で画面に提示され、ユーザーは追記の形を選べる。
- **オーバーレイ**の呼び出しから**中断メモ**の確定および離脱までが、5 打鍵以内で完了する (§4.1 の「数秒で完結」を検証可能にしたもの)。
- **切り替え**の発生時刻と、**中断メモ**が記録されたか否かが履歴として残る。この履歴は SM-C3 の測定基盤であり、ユーザーには表示されない (§5 が禁じるのは表示であって記録ではない)。

#### FR-8: 再開時の位置提示

**ステップ**が再び**現在地**となったとき、システムは当該**ステップ**が属する**タスク**全体における位置と、記録済みの**中断メモ**を提示する。UJ-1 を実現する。

**結果 (検証可能):**
- 提示内容に「第 N ステップ / 全 M ステップ」の形式の位置情報が含まれる。
- **中断メモ**が存在する場合、ユーザーが他の画面を参照することなく読める位置に提示される。

### 4.4 本日計画

**説明:** 毎朝、ユーザーはその日に取り組む**タスク**を順序付きで並べ、時間配分を与える。これは義務ではなく儀式として設計されるが、**本日計画**が存在しなければ**ずれ**と**交差**は検出できない — すなわち本ツールの**介入**機能は**本日計画**に依存する。

#### FR-9: 本日計画の作成

ユーザーは**オーバーレイ**上で、その日の**タスク**を順序付きで選択し、各**タスク**に想定時間を与えられる。

**結果 (検証可能):**
- **本日計画**の作成操作は**オーバーレイ**内で完結し、別アプリケーションを必要としない。
- **本日計画**は開始時刻を持ち、各**タスク**の移行期待時刻は開始時刻に先行タスクの想定時間を累積して定まる。遅延が生じた場合、後続の移行期待時刻は再計算されず、当初の値を保つ (再計算すれば**ずれ**が定義上常に 0 となり検出が成立しないため)。
- 一日について**本日計画**は最大 1 件である。

#### FR-10: 本日計画の不在時の縮退

**本日計画**が作成されていない日において、ツールは**交差**の検出を行わず、それ以外の機能は通常どおり動作する。

**結果 (検証可能):**
- **本日計画**が存在しない場合でも FR-1、FR-7、FR-8、FR-15 は動作する。
- **本日計画**の未作成を理由とする繰り返しの督促は行わない。[ASSUMPTION: 計画作成を促す通知は、それ自体が反射的に無視される**介入**となり、**介入**全体の信頼性を下げるため不要と判断した — 要確認]

### 4.5 観測とずれ検出

**説明:** **常駐プロセス**は最前面のアプリケーション/ウィンドウを**観測**し、その結果を**現在地**および**本日計画**と突き合わせて、**ずれ**・**交差**・**固着**・未宣言の**切り替え**の四つを検出する。これは本ツールが他のタスク管理ツールと決定的に異なる点であり、同時に最大の実装コストとプライバシー上の懸案を伴う。

#### FR-11: アクティブアプリケーションの観測

**常駐プロセス**は最前面のアプリケーションおよびウィンドウの識別情報を継続的に取得し、**現在地**と突き合わせる。

**結果 (検証可能):**
- 取得した識別情報は端末内にのみ保持され、外部に送信されない (§7 参照)。
- OS 権限が未付与の場合、ツールは本機能を無効化した状態で他機能を継続動作させ、その旨をユーザーに示す。

#### FR-12: ずれの検出

システムは**本日計画**が想定する進行と実際の**現在地**の進行を比較し、**ずれ**を算出する。

**結果 (検証可能):**
- **ずれ**は当日中に算出され、翌日以降の振り返りを待たない (JTBD「その日のうちに気づきたい」)。
- 算出された**ずれ**は**オーバーレイ**の初期表示に、**現在地**の位置情報と同じ水準の簡潔さで併記される (FR-2 の例外規定に準ずる)。**介入**の契機とはしない — **ずれ**そのものは中断に値せず、中断に値するのは**交差**である。

#### FR-13: 交差の検出

システムは、**本日計画**が次の**タスク**への移行を要求している一方で**現在地**が**ステップ**の途中にある状態を、**交差**として検出する。

**結果 (検証可能):**
- **交差**の判定は移行期待時刻 (FR-9) の経過と、**現在地**が指す**ステップ**が未完了であることの両者が満たされた時点で成立する。
- 検出は**ステップ**の完了を待たずに行われる (完了を待てば**交差**は既に解消している)。

#### FR-20: 固着の検出

**常駐プロセス**は、**観測**により得られた作業文脈が閾値を超えて変化せず、かつ**現在地**も更新されていない状態を、**固着**として検出する。

**結果 (検証可能):**
- **固着**の判定は**本日計画**を必要とせず、**観測**と**現在地**のみで成立する。
- **固着**の検出は**介入**の契機となる。ただし**介入**の提示内容は未定である (§10 OQ-6)。

#### FR-21: 未宣言の切り替えの推定

**常駐プロセス**は、**観測**された作業文脈が**現在地**の指す**ステップ**と持続的に乖離したとき、ユーザーが宣言しない**切り替え**が発生したと推定し、**現在地**の更新をユーザーに確認する。

**結果 (検証可能):**
- 推定に基づく**現在地**の更新は、ユーザーの確認なしに自動適用されない。
- 確認を求める頻度には上限を設け、乖離が継続する間に繰り返し提示しない。


### 4.6 介入

**説明:** ツールは呼び出しを待たない。**交差**と**休息**の二つの契機において、ツール側から能動的に働きかける。ユーザーは自力でのスケジュール順守と休息確保に失敗しており、静かな通知は反射的に無視されることが既知の失敗様式であるため、**介入**は意図的に強い提示形式を取る。UJ-2、UJ-3 を実現する。

#### FR-14: 交差介入

**交差**が検出されたとき、システムはユーザーに対し強い提示形式で**介入**を発し、二つの選択肢を提示する。UJ-2 を実現する。

**結果 (検証可能):**
- 提示される選択肢は「現在の**ステップ**を完了させてから移行する」「ここで**切り替え**を行い移行する」の二つである。
- 選択肢のいずれかが選ばれるまで**介入**は消えない。単純な無視によって解消されない。
- 「完了させてから移行する」が選ばれた場合、**猶予**の終了時に再度**介入**が発せられる。
- **猶予**の既定値は 15 分とし、ユーザーが変更できる。同一の**交差**に対する**猶予**の付与は 2 回までとし、3 回目の**介入**では「完了させてから移行する」を提示しない。

#### FR-15: 休息介入

連続作業時間が閾値を超えたとき、システムは**休息**を促す**介入**を発する。UJ-3 を実現する。

**結果 (検証可能):**
- **連続作業時間**が閾値を超えた時点で**介入**が発せられる。閾値の既定値は 50 分とし、ユーザーが変更できる。
- 提示される選択肢は「**休息**に入る」「**猶予**の後に再提示する」の二つである。いずれかが選ばれるまで**介入**は消えず、単純な無視によって解消されない (FR-14 と同一の提示形式)。
- 「**休息**に入る」が選ばれた場合、**現在地**は値を保持したまま**非活性**となり、**連続作業時間**の計数が停止する。
- **休息**の終了はユーザーの明示的な操作によって宣言される。終了時に**現在地**は**活性**へ戻り、FR-8 と同じ形式で提示される。
- **休息**の**介入**は**本日計画**の有無に依存しない。

#### FR-16: 決定の記録

**介入**に対してユーザーが行った選択は記録される。

**結果 (検証可能):**
- 記録には**介入**の契機 (**交差**または**休息**)、発生時刻、選択された選択肢、および**猶予**が付与された場合はその回数が含まれる。
- 記録は §5 の非目標に従い、集計・進捗率・連続達成日数のいずれの形でもユーザーに表示されない。

**注記:** 記録された決定の活用方法は v1 では定義せず、記録のみを行う (§10 OQ-5)。

### 4.7 腐敗

**説明:** 過去のプレーンテキスト TODO リストは、肥大化し罪悪感の山に変わったことで放棄された。本ツールは放置された**タスク**を視界から外すことでこれを防ぐ。ただしデータは削除しない — 失う不安は新たな摩擦を生むためである。

#### FR-17: 放置タスクの自動非表示

一定期間**現在地**とならなかった**タスク**は、通常の表示対象から自動的に除外される。

**結果 (検証可能):**
- 除外されても**タスク**および**ステップ**のデータは保持され、削除されない。
- 除外の判定期間はユーザーが変更できる。
- 除外に際してユーザーへの確認や通知は行わない (確認自体が grooming の再発であるため)。

#### FR-18: 腐敗したタスクの復帰

ユーザーは明示的な操作により、**腐敗**した**タスク**を参照し、通常の表示対象へ戻せる。

**結果 (検証可能):**
- **腐敗**した**タスク**は既定の表示経路 (FR-19 の開示面) からは到達できず、専用の明示的な操作を必要とする。
- 通常の表示対象へ戻された**タスク**は、**腐敗**の判定期間が最後に**現在地**となった時点からではなく、復帰した時点から数え直される。
- 復帰は**現在地**を変更しない。**タスク**を表示対象に戻すことと、そこで作業を再開することは別の操作である。

## 5. 非目標

本ツールが「そうならない」ことの宣言である。下流の設計・実装において「ついでに近接する機能を足す」失敗を防ぐ目的を持つ。

- **タスクの網羅的な保管庫にはならない。** 思いついたことをすべて投入する先ではない。投入先として設計すれば、放棄されたプレーンテキスト TODO リストの再来となる。
- **常時の一覧表示を持たない。** 「今日やること全部」「今週の予定」が黙って目に入る画面は設計目標に含まれない (設計上の賭け #1)。明示的な操作による開示面 (FR-19) はこの非目標と両立する — 禁じているのは一覧の存在ではなく、求めていないときに一覧が視界に入ることである。
- **進捗率・消化数・連続達成日数を表示しない。** 達成の可視化は罪悪感の別形態であり、**腐敗**の設計思想と矛盾する。
- **他者に見せるための記録を作らない。** 工数報告、実績管理、およびチームでの共有・割り当て・進捗報告はいずれも対象外である。
- **計画の精度向上を目的としない。** 見積り精度の学習・提案は行わない。本ツールが扱うのは計画の正しさではなく、計画と現在地が食い違ったときの移行である。
- **汎用ランチャーにならない。** グローバルホットキーを持つが、アプリ起動・検索・スニペット展開といった隣接機能へは拡張しない。

## 6. MVP スコープ

v1 が検証する仮説は一つである — **中断地点を記録し再開時に全体の中の位置を返すことで、前のタスクを実際に頭から手放せるようになるか。** この仮説が成立しなければ、**本日計画**も**観測**も**交差**も意味を持たない。したがって最も安価にこの一点を検証できる構成を v1 とする。

### 6.1 スコープ内 (v1)

- **4.1 常駐・呼び出し・既定表示** (FR-1、FR-2、FR-3)
- **4.2 タスクとステップ** (FR-4、FR-5、FR-6、FR-19)
- **4.3 切り替えと再開** (FR-7、FR-8)
- **FR-15: 休息介入** — ただし §6.3 の縮退仕様による

**FR-15 (休息介入) のみがこの論理の外にある。** 仮説検証には寄与せず、§6.3 の縮退により誤発火のリスクを v1 に持ち込む。それでも v1 に含める理由は、身体的 JTBD (適切な休息) が仮説の成否と独立して緊急であり、かつ**観測**の完成を待つ構成では v2 まで一切対処されないためである。これは検証効率ではなく利用者の健康を理由とした意図的な例外であり、他の機能を v1 に引き上げる前例としない。

### 6.2 MVP スコープ外

- **4.4 本日計画** (FR-9、FR-10) — v2。**交差**検出の前提であるため、4.6 と同時に導入する。
- **4.5 観測とずれ検出** (FR-11、FR-12、FR-13、FR-20、FR-21) — v2 以降。実装コストとプラットフォーム依存が最大であり、かつ中核仮説の検証に不要。
- **FR-14: 交差介入** — v2。**本日計画**と**現在地**の双方を必要とするため v1 では成立しない。[NOTE FOR PM] **交差**はユーザーが最も強く訴えた痛みであり、v1 に含まれないことは意図的な先送りである。v1 の使用感次第では優先度を繰り上げること。
- **FR-16: 決定の記録** — v2。FR-15 は v1 スコープであるため技術的には v1 でも成立するが、記録の活用先が定義されていない (§10 OQ-5) ため、記録のみを行う機能を先行させない判断である。
- **4.7 腐敗** (FR-17、FR-18) — v2。v1 では**タスク**総数が小さく罪悪感の山が形成されないため、FR-2 の既定表示最小化のみで当面代替できる。

### 6.3 v1 における縮退仕様

- **FR-15: 休息介入** — **連続作業時間**の定義は §3 のとおり (直近に**現在地**が**活性**となった時点からの経過時間) であり、**切り替え**によってはリセットされない。**観測** (FR-11) が v1 に含まれないため、ユーザーが**休息**を宣言せずに離席した場合、システムはそれを検出できず作業継続中とみなして**介入**が誤発火する。v1 ではこの誤りを許容する。

## 7. 制約とガードレール

### 7.1 プライバシー

**観測** (FR-11) の採用により、本ツールは利用者が一日に使用するすべてのアプリケーションを把握しうる立場に立つ。単独利用であっても、以下を設計上の不可侵条件として明示する。

- **観測**により取得した情報は端末内にのみ保持し、いかなる外部送信も行わない。
- **タスク**、**ステップ**、**中断メモ**を含むすべてのユーザーデータは端末内に保持する。クラウド同期は v1・v2 いずれの対象でもない。
- **観測**により取得したウィンドウ識別情報には保持期限を設け、無期限に蓄積しない。具体的な保持期間は未定である (§10 OQ-4)。
- **観測**を無効化した状態でツール全体が動作すること (FR-11 の結果条件に規定)。

### 7.2 安全性

- **介入** (FR-14、FR-15) は意図的に強い提示形式を取るが、他アプリケーションの操作を奪って不可逆な結果を招いてはならない。
- 特にフルスクリーンでの作業中および入力中に、入力先を奪ってはならない。
- [NOTE FOR PM] 強い提示と入力先の非奪取を両立させる手段は本 PRD では決定せず、UX 設計に委ねる。FR-15 が v1 スコープであるため、これは v1 の設計課題である (§10 OQ-2)。

### 7.3 コスト

- 単独利用の個人ツールであり、継続的な運用費用を前提としない。サーバ側構成要素および有償の外部サービス依存を持たないことを設計制約とする。

## 8. 横断的な非機能要件

- **応答性** — **オーバーレイ**の呼び出しから入力受付までを 300ms 以内とする (FR-1)。この数値は機能要件ではなく製品の前提である。体感として遅ければ、ツールを開くこと自体が中断となり設計原則が崩れる。
- **常時稼働** — **常駐プロセス**は終日動作する。待機時 (**オーバーレイ**非表示かつ**介入**なしの状態) の資源消費を CPU 1% 未満・メモリ 100MB 未満とする。常駐を利用者に意識させないことが要件であり、この数値は検証可能な形でそれを表現したものである。当該上限は v1 の技術選定に対する制約として働く。[ASSUMPTION: この二つの数値および FR-1 の 300ms は実測に基づかない設定値である — 要確認]
- **データ堅牢性** — **現在地**および**中断メモ**は、プロセスの異常終了および OS の強制終了をまたいで失われない (FR-3)。本ツールにおいてこれらの喪失は、防ごうとしている再入コストそのものを発生させる。
- **可搬性** — ドメインロジック (**タスク**、**ステップ**、**現在地**、**中断メモ**、**本日計画**の各モデルと状態遷移) はプラットフォーム非依存に設計する。OS 固有の統合を必要とする点は四つに限定され、いずれも差し替え可能な境界として切り出す — **FR-1** (グローバルホットキーの捕捉)、**FR-3** (ログイン時の自動起動)、**FR-15/§7.2** (最前面での強い提示と入力先の非奪取)、**FR-11** (**観測**)。このうち FR-1、FR-3、FR-15 は v1 スコープである。すなわちプラットフォームの決定は v1 の着手に先行して必要であり、v2 まで延期できない (§10 OQ-1)。

## 9. 成功指標

単独利用のツールであり、定量的な目標値ではなく継続利用と体感の変化によって評価する。

**測定の前提** — SM-2 と SM-3 は導入前後の比較を要求する。したがって **v1 の利用開始前に、現在の自覚 (切り替え後にどの程度前のタスクが頭に残るか、中断からの復帰にどの程度読み直しを要するか) を 2〜3 行で書き留めておくこと。** これを怠ると、v1 の存在理由である指標が測定不能になる。

### 9.1 主要指標

- **SM-1: 継続利用。** 導入から 1 か月後も日常的に使用している。過去のプレーンテキスト TODO リストは放棄に至った — 放棄されないことが最初の成功条件である。製品全体の生存を検証するものであり、個別の FR を切り分けて検証しない。判定は 1 か月後に週あたりの**オーバーレイ**呼び出し日数を目視で確認して行う。
- **SM-2: 手放せた感覚。** **切り替え**の後に前の**タスク**が頭に残り続ける状態が、導入前の書き留めと比べて減ったと自覚できる。中核仮説そのものであり、v1 の存在理由である。FR-7、FR-8 を検証する。

### 9.2 副次指標

- **SM-3: 再入コストの低下。** 中断された作業に戻る際、何をしていたか思い出すための読み直しが導入前より減る。FR-8 を検証する。

### 9.3 逆指標 (最適化してはならない)

- **SM-C1: 登録されたタスクの数。** 増加を目指してはならない。多くの**タスク**が投入されている状態は、網羅的な保管庫化 (§5 非目標) が進行している兆候である。SM-1 を相殺する。
- **SM-C2: ツールの滞在時間。** 長いことは良いことではない。本ツールの理想的な利用は数秒で終わる。増加は**オーバーレイ**が作業の場になりつつある兆候である。SM-1 を相殺する。
- **SM-C3: 中断メモの記入率。** FR-7 の履歴から算出する。低下してはならない。SM-2 は自己申告であり、「手放せるようになった」という自覚は、**中断メモ**を書かなくなった結果として生じることがある — その場合に起きているのはクロージャではなく単なる放棄である。SM-2 を相殺する。

## 10. 未解決の問い

*下流から参照されるため ID を与える。`[v1]` 印は v1 の着手前に決定を要するもの、`[v2]` 印はそれ以降で足りるものを指す。*

- **OQ-1 [v1]: 対象プラットフォームが未確定である。** FR-1 (グローバルホットキーの捕捉)、FR-3 (ログイン時の自動起動)、FR-15 (最前面での強い提示) はいずれも v1 スコープかつ OS 固有の統合を要する (§8 可搬性)。**v1 の実装着手前に決定を要する。** 判断の経緯は `addendum.md` §3.1 に記録した。
- **OQ-2 [v1]: 強い提示形式の具体的な表現が未定である。** 「選択するまで消えない」(FR-15、FR-14) と「入力先を奪わない」(§7.2) を両立させる UI 形式は決まっていない。FR-15 が v1 スコープであるため、**v1 の UX 設計における課題である。**
- **OQ-3 [v2]: 腐敗の判定期間の初期値が未定である (FR-17)。**
- **OQ-4 [v2]: 観測データの保持期間が未定である (§7.1)。** **観測**の取得対象の粒度は §3 で定義済みであるため、残る未決は期間のみである。
- **OQ-5 [v2]: 記録された決定 (FR-16) の活用方法が未定である。** 活用先が定まらないことが FR-16 を v2 へ送る理由そのものである (§6.2)。
- **OQ-6 [v2]: 固着に対する介入の提示内容が未定である (FR-20)。** **固着**の検出条件は定義したが、検出後にユーザーへ何を示すかは決まっていない。
- **OQ-7 [v1]: 製品名が未確定である。** `my-task-manager` は作業用の仮称である。
