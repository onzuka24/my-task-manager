- (decision) 形態: 常駐型 (background実行) + global hotkey overlay。ユーザーが明示的に選好を表明
- (decision) 課題: (1) タスク管理そのものが面倒 (2) タスク切り替えがうまくできていない。この2点が product の核心的 pain
- (decision) 対象ユーザー: 自分用 (solo/personal)。stakes = hobby → PRD は短く保つ (目安2ページ)、Success Metrics は定性で可
- (assumption) [ASSUMPTION] 対象プラットフォームは macOS (開発環境が darwin のため) — 未確認
- (decision) 作業モード: Coaching path / Vision+Features エントリ (capability-first)。セクション順は Vision → Target User → Glossary → Features → Non-Goals → MVP → Success Metrics
- (override) プラットフォーム未確定 (ユーザー回答: Not sure yet)。macOS前提のassumptionは取り下げ、Open Question として扱う
- (decision) タスク切り替えの痛み = (a) 割り込みコスト (b) 固着=切り替えるべき時に切り替えられない。「次に何をやるか選べない」型ではない — 選択の問題ではなく移行の問題
- (decision) 「めんどい」の正体 = grooming (リストが腐って罪悪感の山になる)。capture の手間や入力項目の多さではない
- (decision) 中核課題: 切り替え後も前のタスクが頭に残り、新タスクに集中できない (attention residue)。製品の主戦場は『タスクの記録』ではなく『注意の移行』
- (decision) クロージャの手段 = (a) 中断地点の記録 (b) 全体工程における現在位置の提示 ('全体はNo.1..N、あなたは3にいる')。タスクは平坦な項目ではなく順序を持つ工程として扱う
- (decision) 離脱事例: プレーンテキストのTODOリスト。肥大化し未来のタスクが大量に見えることで『次の一手』に集中できず放棄。→ 既定でリスト全体を見せないことが設計上の必須要件 (Non-Goal に直結)
- (decision) 介入方針: 受動的に待つのではなく能動的に push する。理由はユーザーが (1) スケジュール順守 (2) 適切な休息 の2点で自力管理に失敗しているため
- (decision) データモデル: (c) 両方。タスクは順序を持つステップを内包し、一日は順序を持つタスク列 (計画) を持つ。二階層
- (decision) 最重要: タスク内位置と一日計画の『交差』自体がユーザーの痛み。計画上は次へ進むべきだがステップの切りが悪い、という衝突が固着を生む。競合ツールはどちらか一方しか見ないため検知不能 — 本製品の差別化点
- (decision) ステップは着手前に概ね定義され、詳細は進行中に追記される (完全な事前定義でも完全な創発でもない)
- (decision) 通知は loud (静かな隅の通知では反射的に無視されるため)。具体的な表現形式は未確定
- (decision) 腐敗(Decay): 自動的に表示から外すがデータは保持 (削除しない)。罪悪感の山を『見せない』ことで解決し、失う不安は残さない
- (decision) 観測方式: アクティブウィンドウ/アプリの監視を採用。宣言されていない切り替えと固着を検出可能にするため。代償として OS 権限が必要・実装量最大・プラットフォーム依存が最大化
- (decision) 本日計画: 朝のリチュアルとしてオーバーレイ上で手動作成。カレンダー連携は不採用
- (override) ウィンドウ観測の採用により、プラットフォーム未確定が当該機能に限り阻害要因となる。他機能は移植性あり。Open Question として明示し Finalize でブロッカー判定する
- (decision) ウィンドウ観測により privacy が新たな懸案として発生。Constraints and Guardrails セクションを Adapt-In する
- (decision) MVP = 4.1 常駐/呼び出し + 4.2 タスク/ステップ + 4.3 切り替え/再開 + FR-15 休息介入。本日計画・観測・交差介入・腐敗は v2 以降。中核仮説 (中断地点の記録がタスクの手放しを可能にするか) を安価に検証する意図
- (decision) FR-14 交差介入は選択するまで消えない仕様を維持。固着が敵であり、消せる通知は固着の対象が増えるだけという判断

- (decision) 常駐プロセスの資源上限を待機時 CPU<1% / メモリ<100MB と確定。検証可能な数値とし、v1 の技術選定に対する制約として機能させる。Open Question 6 と対応する ASSUMPTION を解消
