# my-task-manager

## Why

**実現したいビジョンであり、同時に作者自身の具体的な痛みの解決である。** 利用者は作者ただ一人 (solo / personal)。

既存のタスク管理ツールはリストを正確に保つことを目的に設計されているが、実際に生産性を奪っているのはリストの不正確さではなく**切り替えの失敗**である。中断されれば元の場所に戻るのに時間がかかり、切り替えるべき場面で固着して時間を溶かし、切り替えた後も前のタスクが注意残余として残り続けて新しいタスクに集中できない。

したがって本ツールはタスクの保管庫ではなく、**タスクとタスクの「あいだ」を扱う常駐ツール**である。目的は切り替えを速くすることではなく**完了させる**ことにある — 前のタスクが手放されて初めて、次のタスクは注意を受け取れる。

作者は過去にプレーンテキストの TODO リストを放棄している。肥大化し、未来のタスクを大量に可視化し、目の前の一手への集中を奪ったためである。この失敗が本仕様の多くの制約と非目標の出所である。

**スコープ標識** — 各 CAP の `scope` は v1 (最初に作る範囲) と v2 (それ以降) を示す。v1 が検証する仮説は一つ: 中断地点を記録し再開時に全体の中の位置を返すことで、前のタスクを実際に頭から手放せるようになるか。

## Capabilities

- **CAP-1** — 常駐プロセスとホットキー呼び出し `[v1]` `FR-1`
  - **intent:** ユーザーは、いかなるアプリケーションが最前面にあってもグローバルホットキー一つでオーバーレイを呼び出せる。
  - **success:** ホットキー押下から入力受付開始まで 300ms 以内。Esc 単独で閉じられ、閉じた時点で直前に最前面だったアプリケーションがフォーカスを回復する。

- **CAP-2** — 既定表示の最小化 `[v1]` `FR-2`
  - **intent:** オーバーレイは初期状態で次の一手のみを提示し、全体像を見せない。
  - **success:** 初期表示に二つ以上のタスク名または二つ以上のステップ内容が同時に現れない。ただし現在地の位置情報 (「第 3 ステップ / 全 6 ステップ」) は含まれる。

- **CAP-3** — 常駐と自動復帰 `[v1]` `FR-3`
  - **intent:** 常駐プロセスはログイン時に自動起動し、明示的な終了まで動作を継続する。
  - **success:** OS 再起動後、操作なしに常駐している。異常終了しても、切り替え完了時点までに確定した現在地と中断メモが失われない。入力途中の未確定メモは失われてよい。

- **CAP-4** — タスクとステップの定義 `[v1]` `FR-4`
  - **intent:** ユーザーはタスクを作成し、その内部に順序を持つステップを定義できる。ステップの完了を明示的に宣言できる。
  - **success:** ステップを持たないタスクは作成できない。完了は現在地の移動によって自動的に付与も取り消しもされない。

- **CAP-5** — 進行中のステップ追記と分割 `[v1]` `FR-5`
  - **intent:** ユーザーは作業の途中でステップを追加または分割できる。
  - **success:** 連番が再計算されても現在地は同一の作業単位を指し続ける。分割時、現在地は分割後の前半を指し、中断メモも前半に帰属する。

- **CAP-6** — 現在地の一意性 `[v1]` `FR-6`
  - **intent:** 現在地はシステム全体で同時に一つしか存在しない。
  - **success:** 新たなステップが現在地となった時点で直前の現在地は解除される。値を持たない状態は未着手時に限られ、休息中は値を保持したまま非活性となる。

- **CAP-7** — 中断メモの記録 `[v1]` `FR-7`
  - **intent:** 切り替えの際、離脱するステップに対する中断メモの入力機会が提示される。
  - **success:** 入力は省略可能で、省略しても切り替えは完了する。二度目以降は上書きされ、上書き前の内容が記録時に提示される。呼び出しからメモ確定・離脱までが 5 打鍵以内。切り替えの時刻とメモ記入の有無が履歴として残る。

- **CAP-8** — 再開時の位置提示 `[v1]` `FR-8`
  - **intent:** ステップが再び現在地となったとき、タスク全体における位置と記録済みの中断メモが提示される。
  - **success:** 「第 N ステップ / 全 M ステップ」形式の位置情報が含まれ、中断メモが他画面を参照せず読める位置にある。

- **CAP-9** — 全体像の開示面 `[v1]` `FR-19`
  - **intent:** ユーザーは明示的な操作により、タスクとステップの一覧を開示できる。
  - **success:** 初期表示から到達するのに明示操作を最低 1 回必要とする。オーバーレイを閉じた時点で破棄され、次回呼び出し時は初期表示に戻る。腐敗したタスクを含まない。

- **CAP-10** — 休息介入 `[v1]` `FR-15`
  - **intent:** 連続作業時間が閾値を超えたとき、ツール側から能動的に休息を促す。
  - **success:** 閾値の既定値は 50 分で変更可能。選択肢は「休息に入る」「猶予の後に再提示する」の二つで、いずれかが選ばれるまで消えない。休息中は現在地を保持したまま非活性となり計時が停止する。休息の終了はユーザーの明示操作で宣言され、復帰時に CAP-8 と同じ形式で提示される。本日計画の有無に依存しない。

- **CAP-11** — 本日計画の作成 `[v2]` `FR-9`
  - **intent:** ユーザーは毎朝、その日のタスクを順序付きで並べ時間配分を与えられる。
  - **success:** 作成操作がオーバーレイ内で完結する。一日について最大 1 件。計画は開始時刻を持ち、各タスクの移行期待時刻は想定時間の累積で定まり、遅延が生じても後続の期待時刻は再計算されない。

- **CAP-12** — 本日計画の不在時の縮退 `[v2]` `FR-10`
  - **intent:** 本日計画が作成されていない日でも、交差検出以外の機能は通常どおり動作する。
  - **success:** 計画がなくても CAP-1、CAP-7、CAP-8、CAP-10 が動作する。未作成を理由とする繰り返しの督促を行わない。

- **CAP-13** — アクティブアプリケーションの観測 `[v2]` `FR-11`
  - **intent:** 常駐プロセスは最前面のアプリケーション/ウィンドウの識別情報を継続取得し、現在地と突き合わせる。
  - **success:** 取得情報が端末内にのみ保持され外部送信されない。OS 権限が未付与の場合、本機能を無効化した状態で他機能が完全に動作し、その旨がユーザーに示される。

- **CAP-14** — ずれの検出と提示 `[v2]` `FR-12`
  - **intent:** 本日計画が想定する進行と実際の現在地の進行の差分を算出し、ユーザーに気づかせる。
  - **success:** ずれは当日中に算出される。オーバーレイの初期表示に、現在地の位置情報と同水準の簡潔さで併記される。介入の契機とはしない。

- **CAP-15** — 交差の検出 `[v2]` `FR-13`
  - **intent:** 本日計画が次のタスクへの移行を要求している一方で現在地がステップの途中にある状態を検出する。
  - **success:** 移行期待時刻の経過とステップが未完了であることの双方が満たされた時点で成立する。ステップの完了を待たずに検出される。

- **CAP-16** — 交差介入 `[v2]` `FR-14`
  - **intent:** 交差が検出されたとき、強い提示形式で二つの選択肢を示し、決めないまま時間が流れる状態を解消する。
  - **success:** 選択肢は「現在のステップを完了させてから移行する」「ここで切り替えを行い移行する」の二つ。いずれかが選ばれるまで消えず、単純な無視で解消されない。猶予の既定値は 15 分で変更可能、同一の交差に対する付与は 2 回まで、3 回目では完了優先の選択肢を提示しない。

- **CAP-17** — 決定の記録 `[v2]` `FR-16`
  - **intent:** 介入に対してユーザーが行った選択を記録する。
  - **success:** 記録に契機 (交差または休息)、発生時刻、選択された選択肢、猶予の付与回数が含まれる。集計・進捗率・連続達成日数のいずれの形でもユーザーに表示されない。

- **CAP-18** — 固着の検出 `[v2]` `FR-20`
  - **intent:** 作業文脈が閾値を超えて変化せず、かつ現在地も更新されていない状態を検出する。
  - **success:** 判定が本日計画を必要とせず、観測と現在地のみで成立する。介入の契機となる。

- **CAP-19** — 未宣言の切り替えの推定 `[v2]` `FR-21`
  - **intent:** 観測された作業文脈が現在地の指すステップと持続的に乖離したとき、宣言されなかった切り替えを推定し確認を求める。
  - **success:** 推定に基づく現在地の更新がユーザーの確認なしに自動適用されない。乖離が継続する間、確認を繰り返し提示しない。

- **CAP-20** — 放置タスクの自動非表示 `[v2]` `FR-17`
  - **intent:** 一定期間現在地とならなかったタスクを通常の表示対象から自動的に除外する。
  - **success:** 除外されてもデータは保持され削除されない。判定期間は変更可能。除外に際してユーザーへの確認や通知を行わない。

- **CAP-21** — 腐敗したタスクの復帰 `[v2]` `FR-18`
  - **intent:** ユーザーは明示的な操作により、腐敗したタスクを参照し通常の表示対象へ戻せる。
  - **success:** 既定の表示経路 (CAP-9 の開示面) からは到達できず専用の操作を要する。復帰したタスクの判定期間は復帰時点から数え直される。復帰は現在地を変更しない。

## Constraints

- **端末内保持のみ。** サーバ構成要素・クラウド同期・有償外部サービスへの依存を持たない。継続的な運用費用を前提としない。ログ・テレメトリ・クラッシュレポートを含むいかなる外部送信も行わない。自動更新機構もこれに含まれるため持たない。
- **待機時 CPU 1% 未満・メモリ 100MB 未満。** 測定は WKWebView のヘルパープロセスを含む全プロセス合計とする。この上限が実行基盤の選択を実質的に決定しており、超過したまま進めることは許されない。
- **介入は入力先を奪ってはならない。** 強い提示形式を取るが、他アプリケーションの操作を奪って不可逆な結果を招かないこと。特にフルスクリーン作業中および入力中に入力先を奪わない。
- **v1 のビルド対象は macOS のみ。** ただしドメインロジックは OS 非依存に保ち、移植を不可能にしない。OS 固有の統合を要する点は CAP-1・CAP-3・CAP-10・CAP-13 の四つに限定される。
- **用語の一意性。** `glossary.md` の語彙を厳密に使用し、同義語を導入しない。コード上の識別子も同 companion の対応表に 1:1 で従う。
- **抑制は仕様である。** 非目標 (下記) は実装してはならない事項であり、単なる優先度の低さではない。
- **アーキテクチャ不変条件。** `ARCHITECTURE-SPINE.md` の AD-1〜AD-15 は本仕様と同格の拘束であり、実装はそのすべてに従う。

## Non-goals

- **タスクの網羅的な保管庫にならない。** 思いついたことをすべて投入する先として設計しない。投入先として設計すれば、放棄されたプレーンテキスト TODO リストの再来となる。
- **常時の一覧表示を持たない。** 「今日やること全部」「今週の予定」が黙って目に入る画面を作らない。明示操作による開示面 (CAP-9) はこれと両立する — 禁じているのは一覧の存在ではなく、求めていないときに視界へ入ることである。
- **進捗率・消化数・連続達成日数・達成グラフを表示しない。** 達成の可視化は罪悪感の別形態であり、CAP-20 の設計思想と矛盾する。CAP-8 の「第 N / 全 M」は位置情報であって進捗の可視化ではなく、バー・パーセント・色による進捗表現へ発展させない。
- **開示面での一括編集・並べ替え・棚卸しを実装しない。** grooming の再導入にあたる。
- **介入以外の通知・バッジ・音を持たない。**
- **他者に見せるための記録を作らない。** 工数報告、実績管理、チームでの共有・割り当て・進捗報告はいずれも対象外。
- **計画の精度向上を目的としない。** 見積り精度の学習・提案を行わない。扱うのは計画の正しさではなく、計画と現在地が食い違ったときの移行である。
- **汎用ランチャーにならない。** グローバルホットキーを持つが、アプリ起動・検索・スニペット展開へ拡張しない。
- **App Store 配布を目指さない。** CAP-10 の実現に `macos-private-api` が必須であり、恒久的に不可能である。

## Success signal

導入から 1 か月後も日常的に使用しており (過去のプレーンテキスト TODO リストは放棄に至った)、かつ**切り替えの後に前のタスクが頭に残り続ける状態が、導入前に書き留めた自覚と比べて減ったと言える**こと。後者が v1 の存在理由である。

これを偽陽性から守るため、次の三つが同時に成立していなければならない — **登録されたタスク数が増加していない** (保管庫化の兆候)、**ツールの滞在時間が増加していない** (オーバーレイが作業の場になった兆候)、**中断メモの記入率が低下していない** (「手放せた」自覚が、単にメモを書かなくなった結果である可能性を排除する)。三つ目は CAP-7 の履歴から算出する。

測定の前提として、v1 の利用開始前に現在の自覚 (切り替え後にどの程度前のタスクが頭に残るか、中断からの復帰にどの程度読み直しを要するか) を 2〜3 行で書き留めておく必要がある。これを怠ると v1 の存在理由である指標が測定不能になる。

## Assumptions

- 本日計画の未作成に対して督促の通知を行わない。督促自体が反射的に無視される介入となり、介入全体の信頼性を損なうため。
- 待機時 CPU 1% / メモリ 100MB、および CAP-1 の 300ms は実測に基づかない設定値である。誤っていれば実行基盤の選定をやり直す必要が生じる。
- システムのスリープ中は連続作業時間を加算せず、スリープ長が休息閾値を超えた場合は休息が取られたものとみなす。スリープ=離席とみなす扱いは PRD に記述がない。

## Open Questions

- 強い提示形式の具体的な UI 表現が未定である。「選択するまで消えない」と「入力先を奪わない」を両立させる形式は決まっていない。CAP-10 が v1 スコープであるため v1 の UX 課題である。
- 腐敗の判定期間の初期値が未定である (CAP-20)。
- 観測データの保持期間が未定である (CAP-13)。取得対象の粒度は `glossary.md` で定義済みのため、残る未決は期間のみ。
- 記録された決定 (CAP-17) の活用方法が未定である。活用先が定まらないことが CAP-17 を v2 へ送る理由そのものである。
- 固着に対する介入の提示内容が未定である (CAP-18)。検出条件は定義済みだが、検出後に何を示すかは決まっていない。
- 製品名が未確定である。`my-task-manager` は作業用の仮称。
- CAP-18 と CAP-19 が v2 で実装されない場合、アクティブウィンドウ観測 (CAP-13) を採用した根拠そのものが失われる。その場合はタイマー + アイドル検出への降格を再検討すること。
