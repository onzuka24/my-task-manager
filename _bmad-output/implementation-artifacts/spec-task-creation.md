## Intent

**Problem:** **タスク**を作る経路が存在しない。ドメインには `create_task` があるが、そこへ到達するコマンドも UI も無い。**現在地**は `NotStarted` のままで、オーバーレイは「未着手である」としか言えず、**切り替え**は `NoCurrentPosition` で失敗する。前スライスまでの動作確認はすべて `sqlite3` で行を手で入れて行っており、v1 の仮説を 1 か月試すことがそもそもできない。

**Approach:** オーバーレイの中に、明示的な打鍵でのみ到達する**作成の面**を置く。題名と、1 行 = 1 **ステップ**の入力欄を持ち、確定で**タスク**が生まれる。確定の打鍵が二つあり、片方は**現在地**をその**タスク**の第 1 **ステップ**へ置く — 書き留めることと着手することを別の行為として保つためである。CAP-9 の**開示面**には踏み込まない: 既存の**タスク**を並べて選ばせる面を作らない。

## Boundaries & Constraints

**Always:**
- 作成の面は**初期表示に現れない**。明示的な打鍵を最低 1 回経てのみ到達する (FR-2 / AD-15)。
- 作成の面は既存のオーバーレイ (通常ウィンドウ) の中に置く。**三つ目のウィンドウを作らない** (AD-6 が認める提示面は通常ウィンドウと非活性パネルの二種のみ)。テキスト入力を伴うためパネルには置けない。
- **ステップ**の入力は 1 行 = 1 **ステップ**。行の順がそのまま連番 1..N になる。
- 前後の空白を除いたうえで空になる行は**落とす**。落とした結果 1 個も残らなければ作成しない。
- 題名は前後の空白を除いて空であってはならない。**ステップ**を持たない**タスク**は作成できない (FR-4)。
- 確定の打鍵は二つ。片方は作成のみ、もう片方は作成に加えて**現在地**をその**タスク**の第 1 **ステップ**へ置く。既に**現在地**がある場合も同じ規則で、置き換えは後者の打鍵でのみ起きる。
- 下書き (題名・**ステップ**の入力途中の文字列) は揮発ビュー状態であり、確定時にコマンドでコアへ渡す。Esc とフォーカス喪失で破棄されてよい (AD-2 / AD-5)。
- **AD-2 の状態表に下書きの行を追加する。** 表に無い状態を新設してはならないとスパイン自身が定めているため、`ARCHITECTURE-SPINE.md` の表を同時に更新する。
- command は `動詞_名詞`、event は `名詞_過去分詞` (AD-3)。状態を変えた後は必ず event を発行する。
- 面の再描画はスナップショットの取り直しを経由する (AD-3 鮮度規則)。
- IME の変換中の Enter と Escape を、確定とも離脱とも取り違えない (AD-6)。ガードは既存の `onKeydown` と同じく**最初に**置く。
- コマンドは `Core` の不在を既存の `require_core` で扱う。
- 固定サイズのウィンドウの中に収まり、内容が切れないこと (`resizable: false` かつ `overflow: hidden`)。

**Never:**
- 既存の**タスク**の一覧を出さない。二つ以上の**タスク**名、または二つ以上の既存**ステップ**の内容を同時に見せない。**タスク**を選ばせる面を作らない — それは CAP-9 の**開示面**である (FR-19)。
- 並べ替え・一括編集・棚卸しに類する操作を作らない (AD-15 / SPEC 非目標)。
- 既存の**タスク**や**ステップ**の題名・内容を書き換える経路を作らない。**ステップ**の追記と分割 (CAP-5) も本スライスでは作らない。削除も作らない。
- 進捗率・消化数・件数の表示を作らない。登録数を増やすことを促す表現を置かない (SM-C1 は登録数の増加を目標にしてはならないと定める)。
- **切り替え** (CAP-7) と既定表示 (CAP-2) の既存の振る舞いを変えない。

## Implementation Notes

**確定の打鍵を ⌘Enter / ⌘⇧Enter にした理由。** 既定表示の規約は「素の Enter が確定」であるが、作成の面ではそれを踏襲しなかった。**ステップ**の入力欄は 1 行 = 1 **ステップ**であり複数行を打つことが前提であるため、素の Enter を確定にすると 2 行目を打とうとした打鍵がそのまま**タスク**を生む。v1 には削除の経路が無く (CAP-5 の追記・分割も本スライスに無い)、生まれた 1 **ステップ**の**タスク**は取り消せない。素の Enter と Shift+Enter を改行に残し、確定には ⌘ を要求する。⌘Enter が作成のみ、⌘⇧Enter が作成に加えて**現在地**を第 1 **ステップ**へ置く — 修飾キーが増えるほど作用が増えるという既定表示の対応 (Enter / ⌘Enter) はここでも保たれている。案内の行は面ごとに差し替え、効く打鍵とのみ一致させた。

**面へ入る打鍵は ⌘N。** IME ガードより後ろに置き、`switching` の最中には入らない (失敗の理由を読む機会が面ごと消えるため)。到達には明示的な打鍵が 1 回だけ要る (FR-2 / AD-15)。

**行を切り分ける規則はコマンド境界にしか置かない。** `CreateTaskRequest` は**ステップ**を配列ではなく入力欄の文字列そのもので受け取る。配列にすればフロントが行を切り分けて空行を落とすことになり、`as_task_definition` の単体テストが守っているものが実際の経路から外れる。前後の空白の除去・空行の除去・不足の判定はすべてこの純粋関数が持つ (`Task::create` は題名と内容の空白を素通しするため、整えるのは呼び出し側の責務である)。

**作成と現在地の移動を一つのトランザクションにしていない。** AD-5 が単一トランザクションを要求しているのは**切り替え**であり、そこで割れて残る「メモは残ったが**現在地**が動いていない」が禁じられた半端な状態だからである。こちらで割れて残るのは「**タスク**は生まれたが**現在地**が動いていない」であり、これは作成のみの確定が正規に作る状態そのものである。半端な状態が存在しないため、コアへ新しい経路を足してまで束ねていない。`domain/` には一行も触れていない。

**event は二つに分けた。** `task_created` は作成を、`current_position_changed` は**現在地**の移動を伝える。一つに束ねると、作成だけを行う確定が起きていない**現在地**の変化を主張することになる (AD-3)。どちらもペイロードを持たず、受け手はスナップショットを取り直す。

**ウィンドウの高さは変えず、面を辿れるようにした。** 640×280 の内側 (padding 1.75rem を除いて約 224px) に対し、作成の面は題名の欄・**ステップ**の欄 (`rows="3"`)・案内の行で約 157px、失敗の理由を 1 行 + 詳細 1 行で足しても約 204px に収まる。ただし常駐プロセスの状態を伝える警告 (スナップショットの失敗・ホットキーの登録失敗) は面の上に積まれ、この見積りに入っていない。高さを増やす代わりに `main` を `overflow-y: auto` かつ `justify-content: safe center` とし、溢れても切り取られず辿れるようにした (`safe` が無いと溢れた分が上端の外へ出てスクロールでも届かない)。`vitest.config.ts` に `css: true` を足し、この規則を `getComputedStyle` で検証できるようにしている。

**作成が確定した後は決して `Err` を返さない。** `create_task` は**タスク**の永続化に成功した後、第 1 **ステップ**の引き当てと**現在地**の移動が失敗しても `Ok(CreateTaskOutcome { moved: false })` を返し、失敗はログに残す。`Err` を返すと、オーバーレイが「何も保存されていない」と示したうえで入力を保持し、利用者は自然に再確定する — v1 には削除も、既存の**タスク**へ到達する経路 (CAP-9) も無いため、重複した**タスク**は二度と始末できない。オーバーレイは `moved` を読み、作成のみ・作成して着手・作成したが着手できなかった、の三つを述べ分ける。**着手できなかった場合は「作成は済んでいるので同じ入力をもう一度確定しないこと」と明示する。**

**着手先の選択を純粋関数に切り出した。** `step_to_start_from` は連番が 1 の**ステップ**を選ぶ。並びの先頭ではなく連番で選ぶことで、末尾を選ぶ実装に変えたときに単体テストが落ちる。`move_current_position` の呼び出しを消しても `moved: true` を返せてしまう経路も、移動後に**現在地**が実際にそれを指すことを確かめるテストで塞いだ。

**作成の成功後の再描画は `keepDirtyDraft: true` で行う。** 着手を伴う作成は `current_position_changed` を発行し、それを購読する取り直しが `confirmCreation` 自身の取り直しと競走する。二つが同じ規則で走る限り、どちらが後に解決しても結果は同じになる。あわせて、`refresh` の規約 (下書きを捨ててよいのはフォーカス離脱と Esc だけ) も守られる。入力位置は取り直しの後に明示的に**中断メモ**の欄へ戻す。

**押しっぱなしの自動反復を確定として扱わない。** 作成の面は成功と同時に畳まれるため、押し続けられた ⌘Enter の続きがそのまま既定表示へ落ち、生まれたばかりの**ステップ**に対して**完了**の宣言と**切り替え**を撃つ。両方の面の Enter で `event.repeat` を無視する。

**行の区切りは `\n` だけではない。** 単独の `\r` と U+2028 / U+2029 も区切りとして扱う。扱わなければ、貼り付けた複数行が 1 個の**ステップ**に潰れ、内容に制御文字が残ったまま保存される。

**下書きはフォーカス喪失の時点で捨てる。** 取得時にだけ捨てていると、フォーカスのイベントを伴わない再表示が、作成の面を出したままの初期表示になる (FR-2 が禁じる)。

**`user-select` の解除は `app.css` に一度だけ置いた。** 面ごとに書く規則にすると、面を足すたびに書き忘れうる。`input` / `textarea` に一括で掛けている。

## Design Notes

**なぜ確定の打鍵を二つに分けるのか。** 「書き留める」と「着手する」は別の行為である。FR-18 は**腐敗**からの復帰について「復帰は**現在地**を変更しない。**タスク**を表示対象に戻すことと、そこで作業を再開することは別の操作である」と述べており、作成にも同じ原則を当てる。一方、**現在地**が `NotStarted` のままでは作った**タスク**が見えず、**切り替え**も始められない。打鍵で選ばせることで、作業中に思いついた**タスク**を書き留めるだけの経路と、いま始める経路の両方を、追加の打鍵なしに持てる。

**なぜ**タスク**を選ばせる面を作らないのか。** 既存の**タスク**を並べて選ばせた瞬間、それは FR-19 の**開示面**そのものになる。本スライスが扱うのは「新しく書き留める」ことだけであり、既にあるものへ**現在地**を移す手段は CAP-9 が持つ。この線を越えないことが、CAP-9 を二重に作らないための唯一の防壁である。
