## Intent

**Problem:** v1 で唯一の能動的な機能が無い。**連続作業時間**の起点 (`activated_at`) は書かれ復元もされるが、**誰も引き算していない** — 経過時間を読むコードがリポジトリに一行も存在せず、計時そのものも無い。ツールはユーザーの呼び出しを待つだけであり、「スケジュールの逸脱と休息の欠落については能動的に働きかける」という PRD の約束のうち、休息の側が未実装のまま v1 が終わろうとしている。

**Approach:** コアが**連続作業時間**を計り、**休息閾値**を超えたら**介入**を発する。提示は入力先を奪わない非活性パネルで行い、応答は一時登録するグローバルホットキーで受ける — 選ばれるまで消えず、しかし打鍵の行き先を奪わない。「**休息**に入る」なら**現在地**は値を保ったまま**非活性**となり計数が止まる。「**猶予**の後に再提示する」なら 15 分後に出直す。**休息**の終了は、いつものホットキーで呼び出したオーバーレイから明示的に宣言する。

## Boundaries & Constraints

**Always:**
- 計時はコアが行う (AD-8)。フロントエンドは経過時間を数えない。表示する秒数があっても、それはコアから受け取った値の描画である。
- **連続作業時間**の起点は、**現在地**が**非活性**から**活性**へ遷移した時点でのみリセットされる。**切り替えではリセットしない** — リセットすれば、切り替えを繰り返すほど休息が遠のき、最も休息が要る使い方でツールが黙る。
- **休息**中は計数しない。**未着手**および**非活性**のときは**介入**を発しない。
- **休息閾値**の既定は 50 分、**猶予**は 15 分。どちらも設定テーブルに置き、値が無ければコード内の定数を使う (AD-11)。**猶予**による再提示に上限は設けない。
- **介入は同時に一つしか表示しない。** 表示中に別の契機が成立したら後発は待つ (AD-7)。
- 提示は**非活性パネル**で行い、`nonactivating_panel` / `set_hides_on_deactivate(false)` / `full_screen_auxiliary` の**三つをすべて**設定する。いずれを欠いても特定の状況でのみ静かに失敗する (AD-6)。
- パネルは**起動時にメインスレッドで生成し、隠しておく**。`can_become_key_window` は偽とする。スタイルマスクは**加える**のであって置き換えない — 生存中の置き換えはプロセスを異常終了させる。
- パネルに**テキスト入力を置かない** (AD-6)。応答は二択のホットキーだけである。
- 応答のホットキーは**表示のときに登録し、応答で解除する。** 登録と解除を所有するのはコア内の単一の経路であり、**介入**を閉じうる経路が他に存在してはならない (AD-7)。
- **ホットキーのハンドラの中から登録・解除・照会を呼んではならない。** プラグインが同じ錠を保持したままハンドラを呼ぶため、メインスレッドが停止する (上流の既知の不具合)。別のスレッドへ退避してから呼ぶ。
- ホットキーは `Pressed` のみ処理する。1 押下で 2 回発火する (AD-7)。
- **ホットキーの登録に失敗しても介入は出す。** クリックだけで応答できる状態で表示する。登録失敗を理由に**介入**を出さないことを禁じる (AD-7)。
- スリープは、時計の飛びで検出する — 刻みの間隔よりはるかに長い実時間が経過していればスリープである。その長さが**休息閾値**を超えていれば**休息**が取られたものとみなして計時をリセットする。
- **休息**の終了はユーザーの明示的な宣言による。終了時に**現在地**は**活性**へ戻り、CAP-8 と同じ形式で提示される。
- 状態を変えうる操作はコア内の単一の直列化された経路を通す。**休息**への遷移と**切り替え**のコミットが交錯してはならない (AD-5)。
- 待機時 (オーバーレイも**介入**も非表示) の CPU とメモリを**リリースビルドで実測して記録する** (AD-14)。本スライスは常駐 webview を二つに増やし、計時を常時走らせる — v1 で唯一、資源予算に上向きの圧力をかける変更である。
- 既存の 214 件の Rust テストと 96 件の vitest を壊さない。

**Never:**
- **介入**以外の能動的な働きかけを作らない。通知・バッジ・音を持たない (AD-15)。メニューバー項目に残り時間を出さない。
- 進捗率・消化数・連続達成日数・達成グラフを作らない。**残り時間のカウントダウンを常時表示しない。**
- パネルとオーバーレイを同一のウィンドウ実装で兼ねない。生成後にウィンドウ種別を切り替えない (AD-6)。
- **決定の記録** (FR-16)・**交差介入** (FR-14)・**本日計画** (FR-9)・**観測** (FR-11) を実装しない。いずれも v2 である。
- 既定表示・作成の面・開示面・**切り替え**の既存の振る舞いを変えない。**休息**中の表示を足すことは除く。

## Implementation Notes

### 採った形

- **計時の判断は `src-tauri/src/domain/rest.rs` の `decide` 一つに閉じた。** 入力は
  「**現在地**・いまの時刻・直前の刻みの時刻・刻みの間隔・設定値・**猶予**の期限・表示中か」
  の七つ、出力は「付け替え後の起点・付け替え後の猶予・**介入**を発するか」の三つである。
  OS も時計も触らないため、`FixedClock` で全域を検証できる (AD-8)。
- **刻みは 10 秒間隔の専用スレッド 1 本** (`lib.rs::start_ticking`)。非同期ランタイムは
  持ち込んでいない — 眠っている間の費用はスタック 1 本に尽きる。
- **スリープは時計の飛びで検出する。** 刻みの間隔の 3 倍を超える飛びをスリープとみなし
  (`SLEEP_GAP_FACTOR`)、期待されていた 1 回分の間隔を引いた残りを「眠った長さ」とする。
  長さが**休息閾値**を超えていれば起点を `now` へリセットし、超えていなければ起点と
  **猶予**の期限を眠った分だけ後ろへずらす (「加算しない」)。
- **`activated_at` はスリープの補正でのみ「ずれる」。** リセット契機は従来どおり
  **非活性**→**活性**の遷移だけである (AD-8)。ずらした結果は `current_position` の
  コミットとして永続化されるため、補正が再起動をまたいで残る。
- **猶予・介入の表示状態は永続化しない** (AD-2 の表どおり)。失われても次の刻みが
  **連続作業時間**を見て判断し直すだけであり、**介入**が消えるのではなく出直しが早まる。
- **設定値の読み書きの口を `Commit.settings` / `RestoredState.settings` として足した。**
  `V1` の `setting` 表をそのまま使うため、スキーマの版は増やしていない (2 のまま)。
  **休息閾値**と**猶予**は `domain/rest.rs::RestSettings::from_settings` が解釈し、
  値が無い・読めない・0 以下のいずれでもコード内の定数へ落ちる (AD-11)。
- **応答のホットキーは Control+Option+R (休息) と Control+Option+G (猶予)。** 表示の
  ときに登録し、応答で解除する。ハンドラの中からは登録・解除・照会を一切呼ばず、
  `intervention::answer_off_thread` が別スレッドへ退避してから解除する (AD-7)。
- **介入を閉じうる経路は `adapters/intervention::answer` 一つだけである。** ホットキーも
  パネルのクリック (コマンド `answer_intervention`) も同じ関数を通る。コア側では
  `Core::answer_intervention` が「表示中でなければ何も起こさない」を返すため、
  二重発火や競り合った応答で**現在地**が二度動かない。
- **閉じる要求はラベルで分けた** (`lib.rs`)。既存の不具合 — パネルへの閉じる要求が
  オーバーレイを隠していた — を直してある。パネルへの閉じる要求は拒むだけで、
  **介入**は消えない。
- **フロントエンドの入口は一つのまま。** `src/App.svelte` がウィンドウのラベルを見て
  `Overlay` と `Intervention` を描き分ける。入口を割ると Svelte のランタイムが二重に
  積まれ、待機時のメモリ (AD-14) に効く。

### 資源予算の実測 (AD-14)

リリースビルド (`make install`) を `/Applications` に置き、待機状態 (オーバーレイも
介入パネルも非表示) で `./scripts/measure-footprint.sh -a my-task-manager` を実行。
測定対象は responsible pid で束ねた全 7 プロセス (本体・WebKit の GPU / Networking /
WebContent ×2・SandboxHelper・SafariPlatformSupport.Helper)。

| 時点 | メモリ (合計) | CPU (合計) | 判定 |
| --- | --- | --- | --- |
| 起動直後 (~4 分) | 101.0 MB | 0.40% | **超過** (起動直後は落ち着いていない) |
| 起動から ~9 分 | 97.8 MB | 0.23% | OK |
| 同 ~11 分 | 97.8 MB | 0.35% | OK |
| 同 ~12 分 | 97.9 MB | 0.27% | OK |

**待機時の定常値は 97.8〜97.9 MB / 0.23〜0.40% であり、予算 (100MB 未満 / 1% 未満) を
満たす。** ただし**余裕は 2MB しかない。** 本スライスが常駐 webview を二つに増やした
結果であり、AD-14 が予告した上向きの圧力がそのまま表れている。三つ目の常駐 webview を
足す余地は無い。起動直後の 101.0 MB は WebContent が落ち着く前の値であり、定常値では
ないが、**起動後しばらくは予算を超えている**という事実として記録する。

- `the rest threshold was reached; raising an intervention` →
  `intervention panel Show applied` — **閾値超過でパネルが出た**
- 「猶予」で応答 → `intervention panel Hide applied` / `the intervention was answered (Grace)`
- **15 分後に出直した** — 06:29:24 に猶予、06:44:30 の刻みで再提示 (期限 06:44:24 の
  次の刻み)
- 「休息」で応答 → パネルが消え、DB の `current_position` が
  `is_active=0` / `task_id`・`step_id`・`activated_at` はそのまま。
  **値を保ったまま非活性**という受け入れ条件そのものである

## Design Notes

**なぜ「強い提示」が「大きい提示」ではないのか。** FR-15 が求めるのは「いずれかが選ばれるまで消えず、単純な無視によって解消されない」ことであって、視界を占有することではない。PRD §7.2 は逆に「フルスクリーンでの作業中および入力中に、入力先を奪ってはならない」と定める。強さは**消えないこと**で表し、大きさでは表さない — 画面の隅に小さく、しかし答えるまで居続ける形を採る。

**なぜ猶予に上限を設けないのか。** FR-14 (交差介入) は猶予を 2 回までとするが、あれは**本日計画**からの逸脱に対する規律である。**休息**は本人の身体の話であり、三度目に「もう延ばせない」と告げるツールは、**腐敗**が「静かに消えていく」形を選んだこの設計の温度と合わない。上限の代わりに、猶予の長さを設定で変えられるようにする。

**ハンドラの中からホットキーを触ってはならない理由。** プラグインは `shortcuts` の錠を保持したままハンドラを呼ぶ。その中で登録・解除・照会を呼べば同じ錠に再入し、メインスレッドが停止する。`run_on_main_thread` で包んでも、既にメインスレッド上なら即時実行されるため救われない。応答を受けたら、別のスレッドへ退避してから解除する。
