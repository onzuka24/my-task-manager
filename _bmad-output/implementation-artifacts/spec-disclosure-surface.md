## Intent

**Problem:** **現在地**を任意の**ステップ**へ移す手段が存在しない。**切り替え** (CAP-7) の移動先は同一**タスク**内の次の**ステップ**に限られ、作成 (CAP-4) は着手を伴う確定でしか**現在地**を置けない。その結果、着手せずに作った**タスク**へは二度と到達できず、別の**タスク**へ移ることもできない。前二つのスライスはこの穴を「CAP-9 が持つ」として明示的に送っている。加えて FR-19 の**開示面**そのものが未実装であり、**タスク**と**ステップ**の全体像を見る経路が無い。

**Approach:** オーバーレイの中に、明示的な打鍵でのみ到達する**開示面**を置く。**タスク**の見出しは常にすべて見せるが、**ステップ**は一度に一つの**タスク**の分だけ見せる — 初期状態で開いているのは**現在地**の**タスク**である。見出しを確定すればその**タスク**が開き、**ステップ**を確定すれば**現在地**がそこへ移る。移動は**切り替え**であり、**切り替え履歴**を単一のトランザクションで残す — ただし**中断メモ**の機会は与えない。閉じれば面は消え、次回の呼び出しは初期表示へ戻る。

## Boundaries & Constraints

**Always:**
- **開示面**は初期表示に現れない。明示的な打鍵を最低 1 回経てのみ到達する (FR-19 / FR-2 / AD-15)。
- 一覧は**タスク**の見出しをすべて見せる。**ステップ**を見せるのは**一度に一つの**タスク**の分だけ**である — 全部が同時に見えてはならない (設計上の賭け #1)。
- 面を開いた時点で開いているのは**現在地**の**タスク**である。**未着手**のときはどの**タスク**も開いていない。
- 見出しを確定すると、その**タスク**が開き、**直前に開いていた**タスク**は閉じる。** 開いた状態を積み上げられないことが、一覧が全体像へ戻らないための条件である。
- 窓は固定寸法であり、溢れた分はスクロールで到達できること。
- **現在地**が指す行がどれか分かること。
- **完了**した**ステップ**は、書体上の素朴な印で示す。**色・バー・パーセント・件数・進捗率のいずれも用いない** (AD-15)。
- **ステップ**を選ぶと**現在地**がそこへ移る。これは用語集の定義により**切り替え**であり、**切り替え履歴**を残す。**現在地**の移動と履歴の追記は**単一のトランザクション**で確定させる (AD-5)。
- **この経路では中断メモの機会を与えない。** したがって履歴の「メモを書いたか」は常に偽である。機会を与えていない移動を記入率の分子に数えないことが、SM-C3 を歪めないための条件である。
- **完了**に一切触れない。**完了**は**現在地**の移動で自動的に付与も取消もされない (FR-4 / AD-2)。
- 既に**現在地**である**ステップ**を選んだときは何も書かない。履歴も増やさない。
- 面は Esc で閉じ、既定表示へ戻る。オーバーレイを閉じれば破棄され、次回の呼び出しは初期表示である (FR-19)。**開閉状態は保持しない。**
- 面の状態は揮発ビュー状態であり、AD-2 の表の既存の行 (開閉状態・スクロール位置・フォーカス) に収まる。**表に新しい行を足さない** — 足す必要が生じたなら設計が誤っている。
- 表示のたびにコマンドで完全なスナップショットを取得してから描く (AD-3 鮮度規則)。**隠れている間の一覧を持ち越さない。**
- command は `動詞_名詞`、event は `名詞_過去分詞` (AD-3)。新しいコマンドは既存の `switch_current_position` と取り違えられない名前とする。
- 一覧の射影は純粋関数として切り出し、`AppHandle` 無しで検証できるようにする。ドメインの構造体をそのまま線に乗せない — 用途専用の平たい形にし、鍵の集合を固定する検査を置く (既存 4 コマンドの作法)。
- コマンドは `Core` の不在を既存の作法で扱う。
- 既存の 180 件の Rust テストと 56 件の vitest を壊さない。

**Never:**
- 並べ替え・一括編集・棚卸しを促す操作を作らない (SPEC 非目標 / AD-15)。行の移動も削除も改名もこの面から行えない。
- 進捗率・消化数・連続達成日数・達成グラフ、および件数の表示を作らない (AD-15)。「全 M ステップ」のような総数の提示もこの面には置かない。
- **中断メモ**の本文を一覧に載せない。再開時の提示は CAP-8 の既定表示が担う。
- **腐敗** (CAP-20 / CAP-21) を実装しない。v1 に**腐敗**は存在しないため濾すものが無い — ただし v2 で足す際に一覧の取得側を変える必要があることを記録に残す。
- **本日計画** (CAP-11 以降) を実装しない。順序付きの複数選択を先取りしない。
- 常時表示される一覧を作らない。既定表示 (CAP-2)・作成の面 (CAP-4)・**切り替え** (CAP-7) の既存の振る舞いを変えない。

## Implementation Notes

**打鍵は `⌘L`。** Code Map が空いていると記した三つのうち、一覧 (list) と結び付く綴りを選んだ。
`adapters/appmenu` が束縛するのは Z・X・C・V・A の五つであり、`⌘L` はどこにも現れない
(第 1 層の「`⌘Q` はどこにも束縛されていない」を崩さない)。

**開いている**タスク**は要求として送る。** `get_disclosure_surface` は `openTaskId` を
受け取り、`null` を「**現在地**の**タスク**」と読む。開閉は揮発ビュー状態であり所有者は
Svelte である (AD-2 の表「開示面の開閉状態」) — **コアに新しい状態を足していない**。
**濾すのは射影の側である**: 全行を返して描画側で隠す形にすると、線に乗った時点で全体像が
既に渡っており、「見えていないだけ」になる。唯一の欄が `Option` であるため、要求の型は
知らない欄を拒む — 拒まなければ綴りの取り違えが `None` に化け、見出しを確定しても黙って
**現在地**の**タスク**が開き続ける。

**閉じていても**現在地**は分かる。** 凍結節は「**現在地**が指す行がどれか分かること」を
無条件に求めるが、**ステップ**の行だけがそれを負うと、別の**タスク**を開いた瞬間に
**現在地**がどこにも現れない。見出しに `holdsCurrentPosition` を置き、行の側は
`current` のままとした — 前者は「この**タスク**の中にある」、後者は「この行である」。
どちらも**位置情報**であって進捗の可視化ではない (AD-15 が「第 N / 全 M」について
認めているのと同じ類であり、件数・総数・割合・色のいずれも伴わない)。**印は `▸` では
なく `●` である** — 三角は開閉の記号として読まれ、見出しの上では `aria-expanded` と
衝突する。綴りの側も `aria-current` の値で分かれる (`step` と `location`)。

**見出しの確定は一覧だけを取り直す。** 既定表示のスナップショットには触れない — 触れれば
「何も書いていない」はずの操作が、**現在地**を読み直す経路を通ることになる。入力位置は
確定した見出しに留める (開いた**ステップ**へ飛ばすと、閉じるつもりのもう一度の Enter が
見ていない行の上に落ちる)。

**コマンドは `get_disclosure_surface` と `select_step`。** どちらも `動詞_名詞` であり、
`switch_current_position` と取り違えられない。event は新設せず、既存の
`current_position_changed` を**動いたときだけ**発行する — 何も書かない選択でそれを出せば、
起きていない変化を主張することになる。

**一覧を `get_overlay_snapshot` に相乗りさせていない。** 既定表示は表示のたびに必ず取得
されるため、そこに一覧を載せると「隠れている間持ち越さない」を保つ場所が無くなる。取得の
契機が違うものは別のコマンドとした。

**行は内部タグ付きの列である** (`{"kind":"task",…}` / `{"kind":"step",…}`)。見出しに
**完了**の欄が生まれないこと、選べるのが**ステップ**だけであることを、平たい形のまま型で
決めるためである。鍵の集合は `the_disclosure_rows_keep_their_wire_contract` が固定する。

**未着手からの移動には履歴が残らない。** `SwitchRecord` は離脱元の**ステップ**を必ず持ち、
**未着手**には離れる場所が無い — 用語集の定義上それは**切り替え**ではない。欠けた値を
捏造して 1 行積むより、離脱が無かったことを記録の不在で表した。**移動そのものは成立する**
ため、着手せずに作った**タスク**への到達不能はこの経路で解消する
(`selecting_from_not_started_moves_without_a_record`)。

**排他は打鍵の振り分けで担保した。** `onKeydown` は `creating` → `disclosing` の順に面ごとの
ハンドラへ渡して戻る。出ている面は相手へ入る打鍵に触れさせないため、`⌘N` と `⌘L` が同時に
効く状態が構造として存在しない。描画側の連鎖も `creating` を先頭に保った (下書きを抱えて
いるのは作成の面だけであり、一覧は捨ててよい)。

**取得の失敗と移動の失敗を別の変数に分けた** (`disclosureError` / `selectError`)。一つに
まとめると、移動に失敗したときに「一覧を取得できなかった」と述べうる。

**`main` が唯一のスクロール容器のままである。** 一覧に高さも `overflow` も与えていない —

## Design Notes

**なぜ「移動するが、メモの機会は与えない」なのか。** 用語集は**切り替え**を「**現在地**をあるステップから別のステップへ移す操作」と定義しており、この面からの移動もそれに当たる。したがって**切り替え履歴**は残さなければならない — 残さなければ SM-C3 の分母からこの経路が丸ごと消え、記入率が実態より高く見える。一方で、一覧から行を選ぶ操作にメモの入力欄を挟めば、CAP-7 の儀式を一覧の中に作り直すことになり、**開示面**が編集の面へ滑り出す。そこで「移動は記録するが機会は与えない」を選び、履歴の「メモを書いたか」は常に偽とする。**機会を与えていない移動を分子に数えない**ことが、この判断が SM-C3 を歪めないための条件である。

**なぜ `move_current_position` を使わないのか。** あれは履歴を残さない素の移動であり、CAP-6 の一意性を保つためだけの原始操作である。この面から呼べば、移動が記録されないまま**現在地**だけが動く。新しい経路は `switch_current_position` と同じく単一の `Commit` に**現在地**と履歴を載せる — 違いは移動先が同一**タスク**に限られないことと、メモと**完了**に触れないことだけである。

**v2 への申し送り。** FR-19 は「開示面は**腐敗**した**タスク**を含まない」と定めるが、v1 に**腐敗**は存在しないため濾すものが無く、条件は自明に満たされる。CAP-20 を足す時点で、この一覧の取得側に除外を加える必要がある。
